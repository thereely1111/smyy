## 输入

| 参数                                                                      | 路径/来源                                    |
| ------------------------------------------------------------------------- | -------------------------------------------- |
| 知识图谱.json                                                             | `artifacts/{教材名称}/章节目录/知识图谱.json` |
| 体例类型、案例组织模式、案例方向、前置/后置课程、全书总课时、全书计划章数 | 均来自`定位与需求.md`                      |

> 体例模板和案例组织模板位于 `references/`，按需读取。案例检索通过 `../jc-0-知识库检索/scripts/search_kb.py --scope case` 执行。

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

### 目录结构.json

```json
{
  "目标读者": "高职", "体例类型": "项目任务式", "案例组织模式": "综合案例式", "思政_required": false,
  "chapters": [
    {
      "id": "ch01", "title": "第1章 AI产品基础与提示词工程", "chapter_type": "操作类",
      "os": "win11", "tools": ["trae"], "periods": 3.5,
      "children2": [
        { "id": "1.1", "name": "认识AI产品",
          "children3": [
            { "id": "1.1.1", "name": "AI产品的定义与分类",
              "children4": [
                { "id": "1.", "name": "AI产品的定义" },
                { "id": "2.", "name": "AI产品的分类" }
              ]
            }
          ]
        }
      ]
    }
  ]
}
```

| 层级 | 字段                                                      |
| ---- | --------------------------------------------------------- |
| 顶层 | 目标读者、体例类型、案例组织模式、思政_required、chapters |
| 章   | id、title、chapter_type、os、tools、periods、children2    |
| H2   | id、name、children3                                       |
| H3   | id、name、children4                                       |
| H4   | id、name、childrenN                                       |

`chapter_type`：`理论类` / `案例类` / `操作类`。`periods`：总课时（1 课时 = 45 分钟）。`思政_required`：透传自知识图谱.json 的 `meta.思政_required`（true/false）。

| 字段                          | 示例                             | 案例                                                                   |
| ----------------------------- | -------------------------------- | ---------------------------------------------------------------------- |
| type / chapter_id / h2_id     | 所属 H2（`chapter_id` 为数组） | `chapter_id`（数组，全书贯穿式含全部阶段章）/ `chapter_title`      |
| name                          | 示例名称                         | 案例名称                                                               |
| usable                        | `"AI推断"`（固定）             | `"复用"` / `"修改"` / `"补充"` / `"AI推断"`                    |
| kb_entry_id / kb_path         | —                               | KB 来源（AI推断=null）                                                 |
| knowledge_points              | 覆盖的知识点                     | 同                                                                     |
| knowledge_coverage            | —                               | `直接覆盖` / `前章已覆盖(回顾)` / `新增补充` / `AI推断`        |
| modification                  | —                               | 修改/补充内容（复用=null）                                             |
| stages                        | 流程阶段                         | 同；每阶段含`chapter_id`（显式绑定章）与 `kb_part`（命中案例切片） |
| needs_data / data_requirement | `usable="AI推断"`时必填        | 同                                                                     |
| data_flow                     | —                               | 阶段间数据/产物依赖链（全书贯穿式必填，其余模式`[]`）                |

#### 关键字段说明

**`chapter_id`（统一数组）**：所有模式统一用数组表达案例/示例归属的章。

- 单章案例式 / 综合案例式 / 先导实战式：单元素数组，如 `["ch06"]`
- 全书贯穿式：多元素数组，列出案例横跨的全部阶段章，如 `["ch01","ch02","ch03","ch04"]`

**`stages[]` 字段**：

| 子字段              | 说明                                                                             |
| ------------------- | -------------------------------------------------------------------------------- |
| `order`           | 阶段顺序（1 起），全书贯穿式下等于章节顺序                                       |
| `name`            | 阶段名（全书贯穿式下即章标题的案例阶段描述）                                     |
| `chapter_id`      | ★ 阶段显式绑定的章（全书贯穿式必填；单章案例式下等于案例自身 chapter_id）       |
| `knowledge_point` | 该阶段覆盖的知识点编号                                                           |
| `source`          | 阶段来源：`KB`（命中案例切片）/ `AI推断`                                     |
| `kb_part`         | ★ 命中案例的模块名称（粗粒度，如"数据清洗模块"；`source="AI推断"` 时为 null） |

**`data_flow[]`（仅全书贯穿式）**：显式描述阶段间的**运行时数据/产物依赖**，是"严格串行"的调度依据。子字段：

| 子字段          | 说明                                                         |
| --------------- | ------------------------------------------------------------ |
| `from_stage`  | 上游阶段`order`                                            |
| `to_stage`    | 下游阶段`order`                                            |
| `artifact`    | 上游阶段产出、下游阶段消费的产物（如`clean_user_log.csv`） |
| `description` | 依赖说明（一句话）                                           |

> **`data_flow` 的作用**：① 编排智能体据此确定串行等待的具体产物（后章等前章哪个文件）；② 章节生成智能体据此确定本章输入数据来源（`to_stage` 命中的条目即本章输入）；③ 连起来应是一条首尾贯通、不断链的产物链，用于程序化校验"案例流程闭环"硬约束。
>
> **顺序 ≠ 依赖**：`stages[].order` 只表达先后，`data_flow` 表达"依赖什么产物"。只有带产物名的依赖才是串行的真正理由。

## 工作流程（单向流水线）

### Step 0：路径规范（前置确认）

本 Skill **无需建目录**——`write_file` 自动创建多级父目录。

- **输入**（如定位文档、已有目录）：由父编排在 task 中注入**绝对路径**，原样读取，**禁止**用相对路径。
- **产出**：全部产物用**相对路径**写在自己的会话空间（`artifacts/{教材名称}/章节目录/...`），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。主编在**产物面板**查看（面板已聚合本会话 + 子会话产物），无需写父目录。规则见 jc-0 路径工具 §1/§4。

### Step 1：读取与预计算

提取输入参数，按体例+案例模式读取对应模板。读取知识图谱.json（含 `meta.思政_required`）。预计算课时盘：

- 全书理论课时 = Σ(基础×1.5 + 进阶×2 + 高级×3)
- 全书实战课时 = 全书总课时 − 理论课时（理论:实战 ≈ 4:6，非固定）
- 单章实战课时：案例章（`chapter_type="案例类"`）3-4 课时，示例章（理论类/操作类）1-2 课时
- 综合案例式锁定 K（1~3）和 M

### Step 2：设计目录骨架

#### 2.1 确定章数框架

按案例组织模板读取骨架结构：

| 模式       | 章数分布                                                                           |
| ---------- | ---------------------------------------------------------------------------------- |
| 单章案例式 | 1 章理论章 + (计划章数−1) 章案例章                                                |
| 综合案例式 | M 章知识点+示例章 + K 章案例章（M+K=计划章数，K 在 Step 1 锁定，没有知识准备模块） |
| 全书贯穿式 | 计划章数，全部为阶段章                                                             |

#### 2.2 知识点映射

对非案例章逐域映射：域内 3~6→1章，>6→沿依赖链拆分，≤2→合并或独立。

#### 2.3 排序与类型标注

章节顺序由依赖链决定，骨架固定位（综合案例式前 M 后 K）不可变更。按模板标注 `chapter_type`。

#### 2.4 套入体例模板

按体例模板组件树生成 H1~H4 目录，组件顺序和名称不可更改。套用时必须遵守下列体例硬约束：

1. **知识准备 H2 数量**：凡含【知识准备】组件的章，其下**至少 2 个二级标题（H2）**（模板约束「知识准备下至少有两个及以上二级标题」）。
2. **知识准备 ≥ 项目实施**：知识点优先落在【知识准备】侧，【项目实施】不得出现知识准备未铺垫的新知识点（模板约束「知识准备 ≥ 项目实施知识点」）。
3. **综合案例式后 K 章无知识准备**：前 M 章（知识点+示例章）套用完整体例（含【知识准备】）；后 K 章是综合案例章节，不涉及知识点讲解，**不设【知识准备】模块**，仅保留案例实操组件（【项目描述】→【项目实施】等）。

### Step 3：计算课时并写入目录

计算每章总课时（教学+实战），写入目录结构.json 章级 `periods` 字段：

- 理论课时按知识点权重分摊到章（基础×1.5 / 进阶×2 / 高级×3）
- 实战课时：案例章 3-4 课时，示例章 1-2 课时
- 每章 `periods` = 理论课时 + 实战课时；全书 Σ`periods` ≈ 总课时，偏差 ≤ 10%，超限仅微调权重，禁止回退 Step 2

### Step 4：检索案例

仅检索案例（案例章）。通过 `../jc-0-知识库检索/scripts/search_kb.py --scope case` 执行。选最优（覆盖率 > 配套数据集 > 方向匹配 > 难度匹配），选定即排查跨章冲突，无备选标记 `usable = "AI推断"`。

**强制留痕（无论最终处置为何）**：检索命中后，必须输出「KB 命中案例 ↔ 本书知识点」覆盖对照表（逐知识点标注 覆盖/未覆盖/部分覆盖）并计算覆盖率数值，写入案例清单（`knowledge_coverage` 字段 + 案例清单.md 对照表）。禁止以「覆盖不足」为由跳过对照表直接下结论。

### Step 5：缝合与产出

#### 5.1 知识点处置（四路独立判定）

```
案例 = 本章 → 复用
案例 > 本章 → 修改（裁剪超纲；多余知识前章已涉及→回顾，未涉及→新增判定）
案例 < 本章且覆盖 ≥ 40% → 补充（补充缺失知识点）
无候选 或 覆盖 < 40% → AI推断（跳 5.2）
```

**新增知识点判定**：属于前置/后置课程→舍弃；否→必要性判定（依赖链缺失/流程断链/工具被后续依赖，满足任一纳入）。单案例 ≤ 2 个，全书新增 ≤ 10%。纳入后在目录增加 H3 节点。

#### 5.2 AI 推断

三大及格线：体量（单章 small，阶段 4~8 步）、逻辑（100% 对应知识点编号）、业务（紧扣案例方向，含行业真实字段）。填写 `data_requirement`。

#### 5.3 产出

回写目录（新增知识点增加节点）→ 回写章标题 → 确认 `periods` 已写入 → 确认案例和示例已写入案例清单.json（含数据需求）→ 生成四文件。终检：.md↔.json 一致、Schema 合规、知识点编号对齐、**体例硬约束校验**（含【知识准备】的章其 H2 ≥ 2、知识准备覆盖 ≥ 项目实施覆盖、综合案例式后 K 章无【知识准备】组件）。

**全书贯穿式追加产出**：案例条目 `chapter_id` 填全部阶段章数组；`stages[]` 逐阶段填 `chapter_id`（阶段→章显式绑定）与 `kb_part`（命中案例模块名，AI 推断阶段为 null）；`data_flow[]` 按阶段顺序串成一条首尾贯通、不断链的产物依赖链（如 `raw.csv → clean.csv → result.json`），每项填 `from_stage`/`to_stage`/`artifact`/`description`。终检额外校验：`stages[].order` 与 `chapter_id` 顺序一致、`data_flow` 无断链（除首阶段外每阶段都有入边）。

## 导入模式（已有目录 + 无知识图谱）

> 触发条件：编排智能体注入 `【已有目录文档】`（word/md 路径）而非 `【知识图谱路径】` 时进入本模式。

### 输入

| 参数                                                                                          | 来源                                      |
| --------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 已有目录文档                                                                                  | 用户提供的 word/md 路径（编排智能体注入） |
| 体例类型、案例组织模式、案例方向、全书总课时、全书计划章数、操作系统、实现工具/框架、融入思政 | `定位与需求.md`                         |

### 工作流程

#### Step I0：路径规范（前置确认）

本 Skill **无需建目录**——`write_file` 自动创建多级父目录。

- **输入**（如定位文档、已有目录）：由父编排在 task 中注入**绝对路径**，原样读取，**禁止**用相对路径。
- **产出**：全部产物用**相对路径**写在自己的会话空间（`artifacts/{教材名称}/章节目录/...`），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。主编在**产物面板**查看（面板已聚合本会话 + 子会话产物），无需写父目录。规则见 jc-0 路径工具 §1/§4。

#### Step I1：解析目录文档

- word（.docx）→ 解析标题样式（标题1~4），还原为章节树
- md → 读取标题层级（H1~H4）

产出：`{章 → H2 → H3 → H4}` 的原始标题树。

#### Step I2：归一化到体例模板

将原始标题树与体例模板组件树对齐：

- 已含体例组件（【引言】【教学目标】【知识准备】等）→ 直接套用
- 仅纯知识主题标题 → 按体例模板补全组件骨架
- 缺失/冲突组件 → 标记，交由人工闸门确认（不擅自增删章节主题）

> 注意：体例组件名与顺序仍受「模板强制」约束；但用户给定的**章节主题、章数、层级**为既成事实，不套用 Step 2 的"知识点映射/章数框架推导"，仅做结构补全。

#### Step I3：反推目录结构.json 字段

对每个叶子标题补齐：

| 字段               | 来源                                                  |
| ------------------ | ----------------------------------------------------- |
| `chapter_type`   | 由章节语义 + 案例组织模式推断（理论类/操作类/案例类） |
| `os` / `tools` | 透传自`定位与需求.md`                               |
| `periods`        | 由全书总课时按章分摊（复用 Step 3 计算逻辑）          |
| `思政_required`  | 透传自`定位与需求.md`（顶层字段，非来自知识图谱）   |

不生成知识点编号、不建 DAG。案例清单中的 `knowledge_points` 字段改为直接引用章节叶子标题（覆盖关系元数据，下游不消费）。

#### Step I4：案例清单生成

> 前提：目录既定 → 案例的**位置和选题**已由目录标题锁定（案例章标题已写明具体案例，如「案例实战：股票预测AI产品全流程开发」）。本步骤**不再做案例组织模式的章数框架推导，也不再做案例选题**，只做「填充」。若案例选题不确定，才进行案例选题。

- **案例**（案例章）：选题已锁定，按标题主题执行：
  1. KB 检索（`search_kb.py --scope case`）→ 找可复用/修改的真实案例与配套数据集
  2. 四路处置（复用/修改/补充/AI推断），仅用于填充案例**内容与数据**，不改变案例选题
  3. 设计 `stages`（流程阶段，覆盖前置理论章知识点），每阶段填 `chapter_id` 与 `kb_part` → 填写 `data_requirement`
  4. 全书贯穿式：`chapter_id` 填全部阶段章数组，`stages[].chapter_id` 逐阶段绑定章，`data_flow[]` 串成首尾贯通的产物依赖链
- `knowledge_points` 字段：直接引用章节叶子标题（覆盖关系元数据，下游不消费）。

> 关键差异：标准模式里"案例章是第几章、有几个案例"由案例组织模式推导；导入模式里这些已由目录给定，本步骤**不增删案例、不改案例选题**，仅补内容、数据与流程。

#### Step I5：产出与终检

- 产出 `目录.md`、`目录结构.json`、`案例清单.json`、`案例清单.md` 四文件（路径同标准模式）
- 不产出 `知识图谱.md` / `知识图谱.json`
- 终检：.md↔.json 一致、Schema 合规

## 核心约束

1. **流水线**：单向映射，禁止逆向重排
2. **知识点优先**：章节顺序由依赖链决定
3. **1域→1/N章 或 N域→1章**
4. **课时**：全书偏差 ≤ 10%，各章不必均等
5. **案例来源**：KB → AI 兜底
6. **案例处置**：四路独立（复用/修改/补充/AI推断）
7. **模板强制**：体例模板组件不可改，案例组织模板为强制约束
8. **Schema 铁律**：禁止臆造字段

## 修改模式

收到 `[修改指令]` 时：仅修改指出的问题点，逐条对照修正，同步更新全部产出文件。
