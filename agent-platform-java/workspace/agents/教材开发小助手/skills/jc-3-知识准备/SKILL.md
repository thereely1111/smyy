## 工作流程

### Step 1：加载

1. 读取目录结构.json（含 `思政_required`）、知识概要.md（本章「知识准备」部分）
2. 读取资料来源（`_索引.json` → `资料全文/` 下的原文）。**禁止联网补充原文**——原文不完整或缺失时，在产物对应位置标注 `⚠️ 资料原文不完整，需人工补充`，以现有落盘资料为准继续编写
3. 按需加载模板：始终加载 `references/全局写作原则.md` + `例子规范.md` + `用语与格式规范.md`；`思政_required=true` 时加载 `思政融入规范.md`；按 H3 知识类型加载 `references/` 下的结构文件；涉及代码/表格/公式时按需加载对应规范

### Step 2：逐 H3/H4 编写

以知识概要.md（本章「知识准备」部分）的 `content` 为骨架，以资料来源为事实依据，逐 H3/H4 编写。编写顺序：H2 总起段 → 逐 H3 → 逐 H4（如有）。**有示例的知识点，按概要中写明的示例方向选用示例，不得另换示例。**

**按知识类型编写**：根据 H3 标题和知识概要 content 判断类型，加载对应 references 文件。

| 判断条件                                           | 类型         | 加载文件                                       |
| -------------------------------------------------- | ------------ | ---------------------------------------------- |
| 标题/概要含"概念""原理""分类""定义""特点""作用"    | 理论型       | `references/理论型知识结构.md`               |
| 标题/概要含具体方法名/函数名/API/工具操作/代码编写 | 操作型       | `references/操作型知识结构.md`               |
| 标题/概要含"提示词""AI生成""借助AI""驱动AI"        | 提示词驱动型 | `references/提示词驱动型知识结构.md` |

**提示词驱动型结果来源**：来源已有 AI 结果 → 直接引用；来源无结果 → 由内置 AI 真实运行生成的提示词，产出结果，人工核验后写入（详见 `提示词驱动型知识结构.md` 第三、四、六节）。

**提示词驱动型四段式硬约束（强制执行）**：凡判定为"提示词驱动型"的 H3/H4，必须严格输出「描述 → 提示词 → 描述 → 结果」四段式，缺一不可：详细规范见 `references/提示词驱动型知识结构.md` 第三节（四段式）与第四节（代码块标注规则）。

**来源约束（严禁胡编乱造）**：所有方法名、参数、API、技术细节、版本号、运行结果、数据等**必须来自资料来源原文**，逐字核对，不得凭空编造、不得臆测、不得张冠李戴。来源无具体参数 → 标注"具体参数需根据实际场景确定"。来源无对应内容 → 直接不写，禁止自行补造。

**思政判断**：若 `思政_required = true`，可在正文内（示例背景、小提示、结果解释末尾）自然融入思政；若 `false`，不融入。

### Step 3：生成图片清单

知识准备编写完成后，对正文中每个需要配图的位置，遵循 `references/配图规范.md` 的「两步判定」：

1. 先查 KB 图片索引（资料来源为 KB 且原文有图 → 命中直接引用，不纳入清单）
2. 未命中再按配图类型分型（代码生图 / AI生图 / 待补齐）

@图片清单写入知识准备 Markdown 末尾，供 jc-3-视觉素材 批量生成。

### Step 4：代码验证

涉及代码编写时，按 `jc-0-代码验证` 规范执行：本地化 → install.py 安装依赖 → execute_code.py 执行并插入结果 → 失败修复（≤3轮）。

### Step 5：产出

生成知识准备 Markdown → 确认 @图片清单已生成 → 合并代码文件。

## 核心约束

1. **双源强制**：知识准备必须同时依据「知识概要（骨架：讲什么方法、顺序、示例方向）」和「资料来源（事实：方法/参数/结果的具体内容）」，二者缺一不可。不得脱离概要骨架乱写，不得脱离来源编造
2. **来源先行**：先读原文再编写
3. **概要为骨架**：知识概要的 content 决定讲什么方法和顺序，不偏离；有示例的知识点按概要的示例方向选用示例
4. **仅写知识准备**：不编写任务描述、任务分析、任务实现、项目实施
5. **体例强制**：按体例模板的组件结构编写
6. **严禁胡编乱造**：来源无支撑的内容一律不写；方法名、参数、API、版本号、运行结果、数据、引文等所有事实性内容必须可溯源到资料来源原文，不得臆造、不得拼凑、不得张冠李戴
