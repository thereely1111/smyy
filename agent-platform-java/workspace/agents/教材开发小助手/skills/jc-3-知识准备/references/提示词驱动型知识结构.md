# 提示词驱动型知识结构

**适用场景**：AI辅助开发类教材的操作型知识点。来源中包含"任务描述→任务分析→任务实现"结构，且任务分析部分包含"利用AI""借助AI""提示词"等表述，反映人机协作开发模式。

## 判定规则

Skill 在 3b 判定时，当 H3 同时满足以下条件，判定为提示词驱动型：

1. H3 侧重步骤/操作/工具使用/代码编写（满足操作型基本条件）
2. 3a 加载的来源全文中包含明确的"人机协作"信号：
   - 出现"任务描述→任务分析→任务实现"的三段式结构
   - 或出现"人编写提示词→AI输出→人验证"的协作流程描述
   - 或任务分析部分 ≥ 50% 的条目以"利用AI""借助AI""使用AI"开头

> 若不满足上述条件，即使来源是案例类，也按普通操作型处理。

## 一、内部编排结构

编写时的逻辑顺序，**不可颠倒**。输出时用自然段落流，不可显示序号标记。

```
H3/H4标题
  ├─ ① 任务描述（必选）→ 该模块要完成什么目标（1段，来自来源"任务描述"）
  ├─ ② 任务分析（必选）→ 怎么借助AI完成（核心教学点）
  │     ├─ 展示发给 AI 的提示词设计思路（优先引用来源中"任务分析"的原文）
  │     ├─ 若来源有完整的提示词文本 → 用代码块展示（```text 提示词内容）
  │     ├─ 若来源仅有提示词思路描述 → 概括要点，标注"提示词要点"
  │     └─ 说明提示词的设计要点（为什么这样写、关键约束）
  ├─ ③ AI生成结果（必选）→ AI根据提示词产出了什么，按结果来源分两路处理：
  │     ├─ 路1 来源已有结果 → 直接引用来源"任务实现"中的描述/配套代码，不重跑
  │     │     ├─ 有配套代码 → 引用关键代码片段（标注"以下为AI根据提示词生成"）
  │     │     └─ 无配套代码 → 引用来源中的技术实现描述，标注 [来自AI生成]
  │     └─ 路2 来源无结果 → 由内置 AI 真实运行提示词，产出结果，标注为 AI 实际输出
  │           ├─ 运行生成的提示词，得到真实结果（文本/代码）
  │           ├─ 结果须经人工核验后写入，标注"以下为内置 AI 实际运行输出"
  │           └─ 禁止凭空捏造结果冒充 AI 输出（真跑≠编造，运行即为真跑）
  ├─ ④ 人工验证（必选）→ 人如何审查和修正AI的产出
  │     ├─ 引用来源中的"验证要点"或测试结果
  │     ├─ 强调人机协作流程：审查→反馈→AI修正→再验证
  │     └─ 如有实际Bug修复记录，展示"问题→AI定位→修复→验证"过程
  ├─ ⑤ 回顾要点（必选）→ 本节关键提示词模板和协作经验
  └─ ⑥ 收尾过渡（必选）→ 引出下一知识点
```

**6项必选**（任务描述、任务分析、AI生成结果、人工验证、回顾要点、收尾过渡）。

## 二、输出句式

编写时按序自然衔接，不编号：

| 步骤       | 必/可选 | 句式模板                                                      |
| ---------- | ------- | ------------------------------------------------------------- |
| 任务描述   | 必选    | "本节要实现…，目标包括…"                                      |
| 任务分析   | 必选    | "借助AI工具完成本模块开发，关键提示词设计如下："              |
| 提示词展示 | 必选    | 代码块格式：```text 提示词内容 或 概括要点格式：`提示词要点：…` |
| AI生成结果 | 必选    | "将上述提示词输入AI工具，得到以下关键代码/方案："             |
| 人工验证   | 必选    | "AI生成代码后，需要人工审查以下要点：…"                       |
| 回顾要点   | 必选    | "本节的提示词设计要点总结：…"                                 |
| 收尾       | 必选    | "通过以上人机协作流程，我们完成了…，下一节将…"               |

## 三、提示词展示格式规范（强制）

提示词驱动型 H3 中，凡展示「提示词」及其「AI 生成结果」的内容，统一采用「描述 → 提示词 → 描述 → 结果」四段式：

| 段 | 内容 | Markdown 写法 |
|----|------|---------------|
| 描述（前） | 提示词背景、目标、关键约束 | 普通段落 |
| 提示词 | 完整提示词文本 | 题注行 `提示词X-N 标题` + 紧跟 ``` 代码块（文本用 ```text，代码用对应语言） |
| 描述（后） | 设计要点解读、为什么这样写 | 普通段落 |
| 结果 | AI 生成结果 | 按内容类型二选一：**代码** → `代码X-N 标题` 题注 + 代码块；**文本** → `结果X-N 标题` 题注 + ```text 代码块 |

**编号规则**：`提示词X-N`、`结果X-N`、`代码X-N` 为三套独立编号，标签与编号之间**无空格**（与 `图X-N`、`表X-N`、`代码X-N` 约定一致），同章内各自从 1 递增，互不干扰。

**格式要点**：

1. 「提示词」与「结果」均为文本时，用题注行 + ``` 代码块展示；「结果」为代码时，用 `代码X-N` 题注 + 代码块展示
2. 题注行支持 `**提示词X-N 标题**` 加粗写法（md 转 Word 时识别为居中加粗题注）
3. 正文中可通过「如提示词X-N所示」「如结果X-N所示」对提示词/结果做交叉引用

## 四、代码块标注规则（强制）

提示词驱动型 H3 中的代码块，必须标注来源：

| 代码来源                     | 标注格式                                      |
| ---------------------------- | --------------------------------------------- |
| 配套代码中的实际文件         | `以下为AI根据提示词生成的代码（{文件路径}）：` |
| 来源全文中的代码片段         | `以下为AI生成的{功能描述}代码：`              |
| 来源仅描述技术方案，无具体代码 | 只写方案描述，不补充代码；标注 `[来自AI生成方案]` |
| 来源无结果，内置 AI 真实运行 | `以下为内置 AI 实际运行输出的代码：`          |

> **结果来源硬约束（两条路）**：
> 1. **来源已有结果** → 直接引用来源的提示词与结果，不重跑、不编造。
> 2. **来源无结果** → 使用生成的提示词，由内置 AI **真实运行一遍**产出结果，人工核验后写入，标注"以下为内置 AI 实际运行输出"。
>
> **禁止**：凭空捏造结果冒充 AI 输出。区分标准是"是否真实运行"——真实运行提示词得到的输出即为真跑，不属编造；未运行却虚构结果则属编造。

## 五、与传统操作型的区别

| 维度         | 传统操作型                     | 提示词驱动型                         |
| ------------ | ------------------------------ | ------------------------------------ |
| 教学重点     | 教"怎么做"（技术实现）         | 教"怎么让AI做"（提示词工程）         |
| 代码来源     | 教材作者编写                   | AI根据提示词生成，作者验证           |
| 实现部分     | 分步讲解代码                   | 展示提示词→AI输出→人工审查的过程    |
| 验证部分     | 运行代码看结果                 | 强调人工审查AI输出的要点和纠偏方法   |
| 知识传递方式 | 技能传授                       | 协作方法论传授                       |

## 六、来源不足时的降级策略

### 6.1 提示词不足

当来源中"任务分析"部分缺少具体提示词文本（仅写了"利用AI做X"而无实际提示词）时：

1. **可写**：提示词设计思路（从"任务描述"推导提示词应包含的要素）
2. **标注** `[提示词推断]`：正文中注明该提示词为基于来源推断，非原始提示词
3. **不阻塞**：不因缺少提示词原文而阻塞编写，但需明确标注

### 6.2 结果不足

当来源中无 AI 生成结果（只有提示词/思路，无对应输出）时：

1. **路2 处理**：使用生成的提示词，由内置 AI 真实运行一遍，产出结果
2. **人工核验**：核验结果是否与提示词目标一致、是否超纲、是否含敏感内容
3. **标注**：正文注明"以下为内置 AI 实际运行输出"，与来源已有结果区分
4. **不阻塞**：内置 AI 运行失败或结果明显不符时，先标注 `[待运行]`，不阻塞编写流程
