# 操作型知识结构

**适用场景**：工具使用、代码编写、函数/方法介绍、平台操作、语法格式

## 一、内部编排结构

编写时的逻辑顺序，**不可颠倒**。输出时用自然段落流，不可显示序号标记。

```
H3/H4标题
  ├─ ① 概念背景（必选）→ 这个操作涉及的概念先行介绍（1段）
  ├─ ② 操作作用（必选）→ 这个操作用来做什么（2-3句），安装/配置类知识点此处配图
  ├─ ③ 语法/格式（必选）→ 灰底代码块展示基本格式（纯代码操作时输出；安装/配置操作跳过此项，以配图替代）
  ├─ ④ 参数说明（必选，如有参数则输出；无参数则跳过）
  ├─ ⑤ 数据/背景引入（必选）→ 描述示例数据，展示数据表格
  ├─ ⑥ 操作示例（必选）→ 代码 + 题注（或文字描述 + 配图）
  ├─ ⑦ 结果展示（必选）→ 运行输出（或配置完成效果）
  ├─ ⑧ 结果解释（必选）→ 逐行/逐项解读
  ├─ ⑨ 补充/变体/注意事项（可选）→ 有则加
  └─ ⑩ 收尾过渡（必选）→ 引出下一知识点
```

**9项必选**（概念背景、操作作用、语法格式、参数说明、数据引入、操作示例、结果展示、结果解释、收尾过渡）+ **1项可选**（补充/变体）。

## 二、输出句式

编写时按序自然衔接，不编号：

| 步骤     | 必/可选 | 句式模板                                            |
| -------- | ------- | --------------------------------------------------- |
| 概念背景 | 必选    | "XX是一种…" / "在…中，XX是…"                     |
| 操作作用 | 必选    | "XX提供了XX函数用于…" / "使用XX可以…"             |
| 语法格式 | 必选    | "XX的基本语法格式如下。" → 灰底代码块              |
| 参数说明 | 必选    | "XX常用的参数及其说明如表X-N所示。"（无参数则跳过） |
| 数据引入 | 必选    | "以…为例，某数据集的部分信息如表X-N所示。"         |
| 操作示例 | 必选    | "根据表X-N，使用XX函数…，如代码X-N所示。"          |
| 结果展示 | 必选    | "运行代码X-N得到的结果如下。"                       |
| 结果解释 | 必选    | "从结果可以看出…" / "代码中XX参数指定了…"         |
| 补充     | 可选    | "注：此处部分结果已省略。" / "需要说明的是…"       |
| 收尾     | 必选    | "以上介绍了XX的基本用法，能够满足多数情况…"        |

## 三、参数说明表格式规范（严格）

```markdown
| 参数名称 | 参数说明 |
|---------|---------|
| XX      | 接收XX（数据类型用英文）。表示XX。有X个取值：…，默认为XX。 |
```

参数说明结构：**接收XX类型。表示XX（解释参数作用，有多个取值时解释每个取值的含义；取值过多可介绍常用取值）。默认为XX（无默认写"无默认值"）。**

> 注意：参数名与语法格式里的参数名一一对应（不能少或多字母）。默认值与语法格式里的对应。

## 四、安装/配置类操作规范（硬约束）

涉及环境搭建、工具安装、IDE 配置、插件设置等安装/配置类知识点时：

1. **逐步操作**：每一步一个操作，从环境准备到最终验证，不跳步、不合并不描述
2. **逐步配图**：每一步配一张图。关键界面（安装向导、命令行输出、IDE 截图、配置面板、版本验证）必须配图
3. **步骤格式**：`Step N: 操作描述 → 操作目的 → 具体命令/点击路径 → 预期结果 → 配图`
4. UI 截图不通过 `jc-3-视觉素材` 生成，遵循 `references/配图规范.md` 判定规则；无现成截图的标记 `[待补齐]`（人工截取真实界面后替换）

> 此规范覆盖 `操作型知识结构` 中 ②操作作用 和 ⑥操作示例 两步。安装/配置类知识点：②介绍安装目的和前提 → ⑥以分步骤形式展开完整过程（每步配图）。

### 来源不足时的降级策略（硬约束）

当（知识库 / 外部 URL / 图书期刊）**任何来源**仅提供步骤名称但无逐步 UI 交互细节（按钮名、菜单路径、对话框名）时：

1. **严禁编造 UI 路径**：不可凭猜测填写未经来源验证的界面操作。无论来源是 KB、外部网页还是图书，缺失即缺失。
2. **缺失 UI 细节标注** `[待实测]`：流程概述中无法确认的界面元素标注 `[待实测]`，明确告知写作阶段状态
3. **配图降级**：每步配图改为 1~2 张总体界面图；无现成截图的标记 `[待补齐]`（人工截取真实界面后替换）
4. **模型/参数等事实内容**：仅使用来源中实际存在的数据（如 KB 搜索片段中的模型名称表、外部文档中的参数值），不以推测值填充

## 五、Excel/Power BI 工具文字描述规范

非安装/配置类操作步骤使用文字描述，遵循以下用语规则：

1. 界面选项用 `【】` 符号包裹，如 `【开始】选项卡`
2. 需输入内容用 `""` 包裹
3. 操作路径：`【选项卡】>【命令组】>【图标/按钮】>【对话框】`
4. 右键菜单描述："右键单击XX，在弹出的快捷菜单中选择XX"
5. 使用"鼠标""光标""指针"等专业术语
6. 界面中英文名词统一译为中文
7. 数值过大时添加单位（如"销售额（万元）"）
