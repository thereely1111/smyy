## 输入上下文

- **引言组件**：引言（项目任务式）
- **体例类型**：`目录结构.json` 顶层字段「体例类型」= 项目任务式（项目式无独立引言，用项目描述，由 jc-6-项目实现审核 负责）
- **章节目录**：当前章节标题和全书目录

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行方式

**自动化脚本 + AI 语义并列审核。脚本与AI独立运行，合并判定：任一方不通过即为整体不通过。**

### 第一步：运行自动化规则检查
```bash
python scripts/audit_intro.py <待审核内容.md>
```

**脚本输出**（stdout，结构化文本）：

| 检查项 | 说明 |
|--------|------|
| 体例类型 | 项目任务式 |
| 段落结构 | 引言检测 背景→全书关系→内容预览 三段 |
| 行数 | 检测总行数是否在 4~10 行范围 |
| 思政段 | 检测是否有独立的思政融入段落 |

脚本独立输出审核结论（通过/不通过 + 检查项明细）。不产生任何持久化文件。

### 第二步：AI 语义审核
读取被审核文件实际内容，独立输出审核结论。

---

**1. 引言结构（项目任务式）**

- 是否包含 3 部分：背景引入 → 全书关系 → 内容预览
  - 背景引入：由背景/由来/定位/作用等引入本章知识点。工具类章可写发展历程/热点/应用领域；案例类章描述行业发展状况（不描述案例具体情况）
  - 全书关系：本章与本书的关系
  - 内容预览：1~2 行，不超过 3 行
- 总行数是否在 4~10 行范围

**2. 思政融入（引言部分）**

- 引言是否包含 2 部分：思政相关的实事/小故事/典故 + 本章内容引入
- 两部分衔接是否自然
- "二十大" 三个字不能出现在正文中
- 融入字数控制 2 行以内

### 第三步：合并判定

脚本与AI各自独立给出通过/不通过结论。**任一方不通过 → 整体不通过**。汇总双方所有不通过点，统一输出。

## 输出格式

```
[审核结果] 通过 / 不通过

## 脚本审核：[通过/不通过]
（脚本输出的检查项明细：通过项 + 不通过项）

## AI审核：[通过/不通过]
通过项：（列出所有AI通过的检查项）
不通过项：（每项注明具体位置、问题描述、修改建议）

[综合评定]
脚本与AI合并判定：双方均通过 → 整体通过；任一方不通过 → 整体不通过。
汇总双方所有不通过点与修改建议。
```
