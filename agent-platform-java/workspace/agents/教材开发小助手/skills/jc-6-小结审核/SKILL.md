## 输入上下文

- **小结组件**：项目小结
- **章节目录**：当前章节标题树
- **正文内容**：供对比覆盖度
- **教学目标**：供对比目标对应度

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行方式

**自动化脚本 + AI 语义并列审核。脚本与AI独立运行，合并判定：任一方不通过即为整体不通过。**

### 第一步：运行自动化规则检查
```bash
python scripts/audit_summary.py --target <待审核内容.md> --toc <目录结构.json>
```

**脚本输出**（stdout，结构化文本）：

| 检查项 | 说明 |
|--------|------|
| 行数 | 检测项目小结行数，≥3 行通过 |
| H2 覆盖 | 统计小结中提及二级标题的数量，与目录 H2 数对比（`--toc` 传入） |
| 思政段 | 检测是否有独立的思政正面引导段落 |

> 不传 `--toc` 时跳过 H2 覆盖检查。

脚本独立输出审核结论（通过/不通过 + 检查项明细）。不产生任何持久化文件。

### 第二步：AI 语义审核
读取被审核文件实际内容，结合正文和目录进行对比，独立输出审核结论。

---

**1. 内容覆盖（项目小结）**

- 字数不能太少，≥ 3 行
- 内容提取正文中的知识点（参考目录的知识点来写）
- 每个二级标题的内容需在小结中体现
- 小结内容必须在正文中都有介绍
- 是否体现了二级标题之间的联系
- 项目小结需包含知识准备、项目实施的内容

**2. 术语一致性**

- 小结中的术语、概念名称是否与正文保持一致（"对于相同描述的词语，用词必须统一"）

**3. 思政融入**

- 分为 2 部分：知识点总结 + 学习本章后引发的思政正面引导/思考/总结

### 第三步：合并判定

脚本与AI各自独立给出通过/不通过结论。**任一方不通过 → 整体不通过**。汇总双方所有不通过点，统一输出。

## 输出格式

```
[审核结果] 通过 / 不通过

## 脚本审核：[通过/不通过]
（脚本输出的检查项明细：通过项 + 不通过项）

## AI审核：[通过/不通过]
通过项：（列出所有AI通过的检查项）
不通过项：（每项注明具体位置、问题描述、修改建议）

[综合评定]
脚本与AI合并判定：双方均通过 → 整体通过；任一方不通过 → 整体不通过。
汇总双方所有不通过点与修改建议。
```
