## 输入上下文

- **目标组件**：教学目标（项目式 / 项目任务式通用）
- **体例类型**：`目录结构.json` 顶层字段「体例类型」（项目式 / 项目任务式）
- **正文内容**：知识准备 + 项目实现产出，供对比目标对应度

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行方式

**自动化脚本 + AI 语义并列审核。脚本与AI独立运行，合并判定：任一方不通过即为整体不通过。**

### 第一步：运行自动化规则检查
```bash
python scripts/audit_objectives.py <待审核内容.md>
```

**脚本输出**（stdout，结构化文本）：

| 检查项 | 说明 |
|--------|------|
| 条目数量 | 知识目标/技能目标/素养目标 各块条目数（各 3~7 条） |
| 层级关键词 | 统计「了解」「理解」「熟悉」「掌握」「能够」关键词分布 |
| 句式规范 | 技能目标是否使用「能够……」句式 |

脚本独立输出审核结论（通过/不通过 + 检查项明细）。不产生任何持久化文件。

### 第二步：AI 语义审核
读取被审核文件实际内容，结合正文进行对比，独立输出审核结论。

---

**1. 知识目标**

- 数量 ≥ 3 条，≤ 7 条
- 按认知层级由低到高：了解（背景/概念/场景）→ 理解（原理/思想/机制）→ 熟悉（流程/环境/工具）→ 掌握（方法/语法/操作）
- 文中大篇幅编写的理论知识点必须在知识目标中体现
- 不能出现「学习……」「理解……的重要性」等不可测表述
- 不要把知识目标写成纯操作步骤（那是技能目标）
- 每条统一用句号

**2. 技能目标**

- 数量 ≥ 3 条，≤ 7 条
- 使用「能够 + [动作动词] + [对象/技术/任务]」句式
- 不能出现「了解」「熟悉」「掌握」等词
- 文中大篇幅编写的技能点必须在技能目标中体现
- 每条统一用句号

**3. 素养目标**

- 数量 ≥ 2 条，≤ 4 条
- 具体、与本章内容对应，不用虚写（如"爱国"）
- 句式风格全书统一（素养目标句式：通过 [学习活动/实现]，培养 [工匠精神/系统思维/职业素养] 等）
- 每条统一用句号

### 第三步：合并判定

脚本与AI各自独立给出通过/不通过结论。**任一方不通过 → 整体不通过**。汇总双方所有不通过点，统一输出。

## 输出格式

```
[审核结果] 通过 / 不通过

## 脚本审核：[通过/不通过]
（脚本输出的检查项明细：通过项 + 不通过项）

## AI审核：[通过/不通过]
通过项：（列出所有AI通过的检查项）
不通过项：（每项注明具体位置、问题描述、修改建议）

[综合评定]
脚本与AI合并判定：双方均通过 → 整体通过；任一方不通过 → 整体不通过。
汇总双方所有不通过点与修改建议。
```
