| 项目任务式 | 【实训】 | 同上                                       | 同上                                        |

## 工作流程

### Step 1：读取

读取目录结构.json、知识准备内容、项目实现内容、数据文件。

### Step 2：编写实训

三要素：

| 要素           | 内容                                                       |
| -------------- | ---------------------------------------------------------- |
| 训练要点       | 分点列出需掌握的操作类型，不列理论                         |
| 需求说明       | 背景（贴近读者生活）+ 现状 + 目标                          |
| 实现思路及步骤 | 分点列出实现目标的步骤，尽量详细（如"使用…方法，进行…"） |

不得与正文/项目实现已有操作重复，但可用同一工具/方法完成新任务。

### Step 2.5：数据需求判断

编写实训时，判断该实训是否需要数据：

- **需造新数据**：当实训需要"贴近生活的新场景"数据时，现场生成一份 `data_requirement`（`data_types` + `fields` + `rows` + `说明`），通过**调用 jc-2-数据准备**，传入该需求，由其按三级优先级准备数据。

### Step 3：编写答案

以 `【答案】` 隔开，含参考代码时标注路径：`artifacts/{教材名称}/第X章_{标题}/实训答案/实训N/`。

### Step 4：数据与代码组织

数据需求已在 Step 2.5 判定（复用 or 调 jc-2 造新）。

**代码与数据存放**：实训答案的代码和数据统一存放到 `artifacts/{教材名称}/第X章_{标题}/实训答案/实训N/`（N 为实训编号，如实训1、实训2），代码文件和所用数据文件同目录存放，不区分代码/、数据/ 子层。

### Step 5：产出

生成实训 Markdown。

## 核心约束

1. 三要素完整（训练要点+需求说明+实现思路及步骤）
2. 不得与正文已有操作重复
3. 内容不超纲，贴近读者生活
4. 必须有【答案】，含代码时标注路径

## 修改模式

收到 `[修改指令]` 时：仅修改指出的问题点，逐条对照修正。
