## 工作流程

### Step 1：读取

读取目录结构.json（本章标题、技术方向、`思政_required`）、知识概要.md（本章知识点）。

**思政判断**：若 `思政_required = false`，本章不编写阅读拓展（阅读拓展本质为思政内容）；若 `true`，按后续步骤编写。

### Step 2：选择素材方向

阅读拓展从以下 4 类素材中提取与本章技术相关的内容导读：

| 素材方向 | 说明 |
|----------|------|
| 政府报告原句 | "十五五"规划、二十大报告等相关原句 |
| 行业/企业优秀代表 | 人物 |
| 技术应用优秀事件 | 事件 |
| 优秀产品新闻报道 | 物（开源产品优先） |

> **优先国产内容**；可询问 AI 但需核实结果的准确性。

### Step 3：编写导读

导读的编写流程：

1. **找例子**：优先正文提到的应用场景，或能体现本章技术优势的场景；核实例子的真实性
2. **引入思政**：从该行业领域出发找思政元素，优先"十五五"规划或二十大报告原句
3. **正式编写**：以思政元素引出场景/例子，从思政元素引出行业领域和技术应用，不生硬

导读要素：

| 要素 | 说明 |
|------|------|
| 与技术结合 | 导读内容与本章技术方向紧密结合 |
| 体现思政 | 引导读者树立正确思想，走正确道路 |
| 科普前沿（建议） | 科普与本章相关的前沿技术 |

> **引用政府报告原文（硬约束）**：必须用报告原文，一字不漏、一个符号都不能改；不要对引用的思政原文进行解读。详见 `references/思政融入规范.md`。

### Step 4：编写思考题

与导读内容或本章技术相结合，不可脱节。

### Step 5：产出

生成阅读拓展 Markdown。

## 核心约束

1. 导读与本章技术结合
2. 思考题与导读不脱节
3. 引用政府报告原文时一字不改、不可解读
4. 各章阅读拓展尽量使用不同的思政元素

## 修改模式

收到 `[修改指令]` 时：仅修改指出的问题点，逐条对照修正。
