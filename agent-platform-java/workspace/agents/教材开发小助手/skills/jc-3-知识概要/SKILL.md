## 输入

| 参数             | 路径                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------ |
| 目录结构.json    | `artifacts/{教材名称}/章节目录/目录结构.json`                                         |
| 案例清单.json    | `artifacts/{教材名称}/章节目录/案例清单.json`（仅项目实现消费案例；案例清单不含示例） |
| 各章资料查找结果 | `artifacts/{教材名称}/第X章_{标题}/资料全文/第X章_资料来源.md`（全书所有章）          |

> `思政_required` 从 `目录结构.json` 顶层字段读取，不依赖知识图谱。案例清单已不承载「示例」，知识准备的示例由本 Skill 自行推断。

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 规范

资料查找结果决定每个知识点能讲什么——KB 命中的来源覆盖了哪些方法，概要就写哪些方法。没有来源支撑的方法不凭空编造。

知识准备的示例由本 Skill 自行判断是否配、配什么方向（案例清单已不承载示例），判定标准见「示例必配原则」。

## 输出

- **全书一个文件**：`artifacts/{教材名称}/章节目录/知识概要.md` —— 用**相对路径**写在自己会话空间，并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）（主编在闸门3 看摘要、在产物面板打开文件）
- **结构**：按章组织，每章内分「知识准备」和「项目实现」两部分
- **不经一审**：知识概要由主编在 👤闸门3 直接确认

## 输出格式

```markdown
# 全书知识概要

## 项目1 {章标题}

### 知识准备

#### 1.1 {标题}
- content_flow：首先认识[方法/概念A]→然后掌握[方法/概念B]→最后……（本 H2 讲哪些知识点、按什么顺序）
- children：
  - 1.1.1 {标题}：先介绍[方法A全称]（来源：……）→再说明[方法B全称]（来源：……）→……（逐知识点讲方法与概念，标注来源，不涉及案例与交付物）

### 项目实现

#### 1.2 {标题}
- content_flow：步骤1→步骤2→步骤3→……（本 H2 的完整步骤顺序）
- children：
  - 1.2.1 {标题}：步骤1 {简要说明}→步骤2 {简要说明}→步骤3 {简要说明}→……（只写步骤顺序 + 每步简要说明，不展开细节）

## 项目2 {章标题}
……
```

> 各章正文编写时，从本文件自行选取本章对应部分。jc-3-知识准备 只读取本章「知识准备」部分，jc-3-项目实现 只读取本章「项目实现」部分。

## 工作流程

### Step 1：读取

读取目录结构.json（全书章节树 + `思政_required`）、案例清单.json、各章资料查找结果（`第X章_资料来源.md`）。

### Step 2：逐章逐标题编写

遍历全书所有章的 H2→H3→H4，每章分「知识准备」和「项目实现」两部分，**两部分的结构不同，分别按以下规范编写**。

#### 【知识准备】

依据：该章资料查找结果（讲哪些方法/概念）。

- **H2**：写 `content_flow`——本 H2 讲哪些知识点、按什么顺序（`首先认识[方法/概念A]→然后掌握[方法/概念B]→最后……`）。
- **H3/H4**：写 `content`——逐知识点讲方法与概念，格式：`先介绍[方法A全称]（来源：……）→再说明[方法B全称]（来源：……）→……`。方法名必须写全称，不可笼统；**必须标注来源**；**不涉及案例，不写交付物**。

**示例必配原则**：知识准备的示例由本 Skill 按以下规则自行判定「配不配」与「配什么方向」：

1. **必配示例的知识点**：函数方法、操作性知识点、易混/易错点、后文案例依赖的知识点——**必须配一个示例**，content 中写明示例方向；
2. **可不配示例的知识点**：简单陈述性概念——可不配；
3. **示例方向来源**：须基于该章资料来源或自行推断，示例自包含优先；**严禁使用项目实现的案例作为知识准备的示例方向。**

#### 【项目实现】

**定位**：基于知识准备已讲的知识点，完成该章的案例或综合示例。**只写步骤顺序 + 每步简要说明，不展开细节、不额外讲知识点。**

依据：知识准备内容（知识点，是实现的依据）+ 案例清单中的案例（用什么案例来应用这些知识点）。

- **H2**：写 `content_flow`——本 H2 的完整步骤顺序（`步骤1→步骤2→步骤3→……`）。
- **H3/H4**：写 `content`——该 H3/H4 的步骤顺序 + 每步简要说明，格式：`步骤1 {简要说明}→步骤2 {简要说明}→步骤3 {简要说明}→……`。**每步只写一句话简要说明做了什么**（可体现所复用知识点、案例名、产出交付物，但点到为止），**不展开操作细节、不写提示词全文、不额外讲知识点**。

**步骤顺序来源**：

1. **优先**：案例清单中该案例已有步骤（如 `stages[]` 阶段顺序、`data_flow[]` 依赖顺序）→ 直接照其顺序展开每一步；
2. **兜底**：案例清单未给出步骤时，按该章知识准备的 `content_flow`（知识点先后顺序）推导实现步骤，每一步操作须对应一个已讲知识点。

> **案例来源**：项目实现复用案例清单中的案例（`stages[]`、`data_flow[]`），不复用知识准备的示例方向。

### Step 3：产出

只生成调用方注入的**批次章节范围**内各章的知识概要：首批判新建 `章节目录/知识概要.md`，后续批次在既有文件末尾**追加**（已存在的章节禁止重复写入）。

## 核心约束

1. **按批生成**：每次只产出批次章节范围内各章的概要（每批 ≤4 章，由调用方指定），追加进 `知识概要.md`；禁止越界生成范围外的章，禁止重复写已有章节
2. **逐级到底**：每个标题都必须有概要
3. **两部分结构不同**：知识准备 content 用"→"串联具体方法/概念全称 + 来源，讲方法不涉案例；项目实现 content 只写步骤顺序 + 每步简要说明（`步骤1 {简要说明}→步骤2 {简要说明}→……`），不展开细节、不额外讲知识点
4. **示例要写明**：知识准备中满足「示例必配原则」的知识点，content 中必须写明示例方向（用什么例子），不得只写方法不写示例；示例方向由本 Skill 自行按资料来源推断，**严禁使用项目实现的案例/综合示例方案作为示例方向**
5. **来源驱动**：概要中的方法与示例须基于各章资料查找结果，未覆盖的不编造
6. **跨章一致**：全书各章术语、方法命名保持一致；全书贯穿式下后章复用前章方法处显式标注「复用不重讲」

## 修改模式

收到 `[修改指令]` 时：仅修改指出的问题点，逐条对照修正，同步更新 `知识概要.md`。
