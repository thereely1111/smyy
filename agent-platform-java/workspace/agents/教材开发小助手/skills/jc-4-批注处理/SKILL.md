# jc-4-批注处理

## 定位

章节交付智能体（jc-5）名下的批注处理 Skill。主编在转 word 产出的 `.docx` 成品上**原地批注**后，本 Skill 完成「提取批注 → 分析批注（翻译成修改要求）→ 定位源组件 + 生成修改指令」三段式处理。

**职责边界**：本 Skill 只做「理解批注 + 翻译成修改要求」，**不生成改后全文**。具体文字改写由 jc-3 修改模式完成（jc-3 有资料来源、写作规范、全书术语一致性，改出的文字才符合教材标准）。

处理结果（修改指令清单）回传编排智能体，由编排智能体调度章节生成智能体（jc-3 修改模式）按修改要求生成改后文本，再调度章节交付智能体（jc-5）重新拼装转 word。

## 输入上下文

- **带批注的 .docx**：`artifacts/{教材名称}/第X章_{标题}/第X章_{标题}_v{版本}.docx`（主编原地批注）
- **章节目录**：`artifacts/{教材名称}/章节目录/目录.md` + `目录结构.json`
- **源组件目录**：`artifacts/{教材名称}/第X章_{标题}/组件/`（供定位源组件）

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行方式

> **批注产物存放约定**：所有批注相关文件统一写入 `artifacts/{教材名称}/第X章_{标题}/批注/` 目录，文件名带源 docx 版本号（如 `_v1.0`），多轮批注按版本归档、互不覆盖。

### 第一步：提取批注

```bash
python scripts/extract_docx_comments.py <带批注.docx> --output json --output-path "artifacts/{教材名称}/第X章_{标题}/批注/第X章_{标题}_v{版本}_批注汇总.json"
```

产出批注清单（JSON）：每条含 `id / author / date / text（批注原文）/ context（锚定处原文）`。

### 第二步：批注定位章节 + 分析合理性 + 生成修改方案

```bash
python scripts/map_comments.py <批注.json> <带批注.docx> > "artifacts/{教材名称}/第X章_{标题}/批注/第X章_{标题}_v{版本}_批注映射.json"
```

产出增强批注清单：每条补 `mapped_para_index`、`section`（所属章节标题）和 `component`（组件归属）。

随后 AI 逐条分析（三维度判断合理性 + 制定修改方案）：

| 维度 | 判断标准 |
|------|---------|
| 专业准确性 | 批注指出的术语/概念是否准确、符合行业规范 |
| 教学有效性 | 修改后是否降低认知门槛、利于知识迁移 |
| 规范符合度 | 是否符合层次编号、图表引用、过渡衔接等格式要求 |

- 满足任一维度 → **合理**，制定修改方案
- 部分可取 → **部分合理**，标注可取部分
- 全不满足 → **不合理**，给出拒绝理由（回传主编）

每条"合理/部分合理"批注，将批注**翻译成修改要求**（不写改后全文）：修改位置 + 修改方式（替换/插入/删除）+ 修改要求（改什么、改成什么方向）+ 修改说明。

### 第三步：定位源组件 + 生成标准修改指令

```bash
python scripts/map_to_components.py <增强批注.json> <组件目录> --output "artifacts/{教材名称}/第X章_{标题}/批注/第X章_{标题}_v{版本}_批注修改指令.json"
```

将批注的 `component`（组件归属，已在第二步判定）映射到源组件 md 文件，并生成标准 `[批注修改指令]`：

```
[批注修改指令]
目标组件: {组件名}（引言/教学目标/知识准备/项目实现/项目小结/实训/课后习题/阅读拓展）
章节: 第X章
批注ID: {id}
定位锚点: {H3标题 / 段落原文 / 图X-N / 代码X-N}
修改方式: 替换 / 插入 / 删除
修改要求: {改什么 + 改成什么方向，如"将背景场景更换为更贴合当下的场景，保持原有三段结构"}
修改原因: {批注原文}
优先级: P0 / P1 / P2
[/批注修改指令]
```

> 注：`修改要求` 只给「改什么 + 方向」，**不给改后全文**。具体文字由 jc-3 修改模式依据资料来源、写作规范、全书术语一致性生成。

**源组件定位规则**（Word 标题 → 组件映射）：
- `section` 含「引言」→ 组件/引言.md
- 含「教学目标/学习目标」→ 组件/教学目标.md
- 含「思维导图」→ 组件/导图（.xmind/.png，非 md）
- 含「知识准备/知识讲解」→ 组件/知识准备.md
- 含「项目实现/项目实施/任务实现」→ 组件/项目实现.md
- 含「项目小结/小结/总结」→ 组件/项目小结.md
- 含「实训」→ 组件/实训.md
- 含「课后习题/习题」→ 组件/课后习题.md
- 含「阅读拓展/拓展」→ 组件/阅读拓展.md

**图片批注处理规则**（批注锚定在图片上，context 含 `[图片:xxx.png]` 标记时）：

图片批注的 `context` 由脚本兜底生成，格式为 `[图片:{文件名}] {前段文本} {后段文本}`。处理时：

1. **定位图片**：从 `[图片:xxx.png]` 提取图片文件名（对应 docx 内的 `media/` 文件），结合 section（向上追溯最近标题）确定图片所属章节和位置。
2. **判断图片来源 → 路由到对应生成 Skill**（批注处理只生成修改指令，不直接改图）：

| 图片来源 | 修改方式 | 路由 |
|---------|---------|------|
| 思维导图（section 含「思维导图」） | 重新生成导图 | `jc-3-思维导图`（依据批注内容重新生成 .xmind/.png） |
| AI 生图 / 代码生图 | 重新生成图片 | `jc-3-视觉素材`（改生成参数/绘图代码重跑） |
| KB 下载图 / 截图 | 替换素材或标注待补齐 | `jc-3-视觉素材`（找替代素材，无则标 `[待补齐]`） |

3. **修改指令格式**：`目标组件` 填对应生成组件（思维导图/视觉素材），`定位锚点` 填 `图X-N`（题注）或图片文件名，`修改要求` 写"重新生成图片 + 改什么方向"（如"重绘流程图，增大节点间距使布局更疏朗"）。

## 输出格式

```
[批注处理结果]

## 批注概览
共 {N} 条批注，合理 {A} / 部分合理 {B} / 不合理 {C}

## 修改指令清单
（按组件分组的 [批注修改指令] 列表，供 jc-3 修改模式消费）

## 不合理批注说明
（每条不合理批注的拒绝理由，回传主编）

## 修改优先级
P0（影响面大）/ P1（核心能力）/ P2（快速修改）
```

## 注意

- 批注版 .docx 原地批注，**保留存档**（作为批注记录），修改后重新转 word 产出新版本（版本号主版本 +1）
- 批注产物（批注汇总 / 批注映射 / 修改指令）统一写入 `批注/` 目录，文件名带源 docx 版本号，**多轮批注按版本归档、互不覆盖**
- 修改完成后重新走：拼装 → 通读内审 → 转 word，**不重走一审**（批注是主编终审意见）
- 思维导图组件的批注：返回 jc-3-思维导图**重新生成**（.xmind/.png 由 jc-3 生成，依据批注内容重新生成即可，无需 jc-3 修改模式）
