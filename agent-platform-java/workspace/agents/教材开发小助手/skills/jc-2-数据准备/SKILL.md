## 输入

| 参数 | 说明 |
|------|------|
| 案例清单.json | （输入源 A）读取 `items` 中 `usable = "AI推断"` 且 `needs_data = true` 的条目，取其 `data_requirement` |
| data_requirement（调用方传入） | （输入源 B）实训/操作题现场生成的数据需求，直接传入。字段同案例清单的 `data_requirement`：`data_types`、`fields`、`rows`、`说明` |

> 两种输入源可单独或同时存在。输入源 B 用于 jc-3-实训生成 / jc-3-课后习题 在编写阶段现场判断"需新数据"后直接调用本 skill。

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行步骤

### Step 1：提取数据需求

数据需求有两个来源，合并处理：

- **输入源 A（案例清单）**：从案例清单.json 的 `items` 中筛选 `usable = "AI推断"` 且 `needs_data = true` 的条目，取 `data_requirement`。
- **输入源 B（调用方传入）**：实训/操作题现场生成的 `data_requirement`，直接作为数据需求。

读取每个需求的 `data_types`、`fields`、`rows`、`说明`，确定目标数据形态。

### Step 2：KB 数据库拉取（优先级 1）

**检索词构造**：用 `data_requirement` 的 `说明`（中文数据描述）作为主检索词；`说明` 缺失时用 `case_domain`（案例领域）或 `name`（案例名）作为检索词。检索词须简洁（核心名词，如"股票 历史行情"，不含"约500~2000行"等量词描述）。

通过 `../jc-0-知识库检索/scripts/pull_datasets.py` 的 `pull_datasets(keyword, output_dir)` 搜索并下载匹配数据集到目标路径（`数据/{数据集名}/`）。至少 1 个有效文件成功存入 → 完成。

### Step 3：外部搜索 + AI 自动获取（优先级 2，仅「知识库+互联网」模式）

> **资料来源模式（取父任务注入值，未注入一律按「仅知识库」）**：「仅知识库」模式下**本步骤整体跳过**（不调用 web_search、不抓取任何外部平台/官网），直接进入 Step 4；其中「路径 B：Python 库自带数据」属本地代码加载、非联网收集，移至 Step 4a 两种模式均可用。

仅当 `资料来源模式=知识库+互联网` 时，按以下路径执行：

**路径 A：外部数据集平台** — web_search 找公开数据集：

| 平台 | URL |
|------|-----|
| Kaggle | https://www.kaggle.com/ |
| 天池 | https://tianchi.aliyun.com/ |
| 和鲸社区 | https://www.heywhale.com/home/dataset |
| 数据开放平台 | 搜索"数据开放平台" + 行业关键字 |

**路径 B：Python 库自带数据** — sklearn、seaborn、statsmodels、akshare 等，代码加载后导出 CSV/Excel。

**路径 C：官方网站爬取** — 数据来源于具体机构/平台的官方网站时，从官网抓取公开页面。适用于任何可从网站公开页面采集到的数据，常见场景包括（但不限于）：

| 数据类型 | 典型来源 | 说明 |
|---------|---------|------|
| 招牌/商户数据 | 本地生活平台（如大众点评、美团）公开商家列表页 | 店铺名称、分类、评分、地址、营业时间等 |
| 新闻/资讯数据 | 新闻门户/媒体官网公开栏目页 | 标题、发布时间、正文、来源、分类等 |
| 商品/价格数据 | 电商平台公开商品列表页 | 商品名、价格、销量、评价等 |
| 企业/招聘数据 | 招聘网站、企业官网公开职位页 | 职位、薪资、要求、地点等 |
| 榜单/排行数据 | 官网公开榜单页（票房、热搜、销量榜等） | 名称、数值、排名、时间等 |
| 公开统计数据 | 政府/机构官网公开数据页 | 指标、数值、地区、年份等 |

> 判断标准：只要目标数据能从某官方网站的**公开页面**采集到，且无登录/验证码/反爬限制，即可优先采用官网爬取，而非脚本造数据。

规范：
1. **仅爬公开页面**：只抓取无需登录、robots.txt 未禁止的公开列表/栏目页，不绕验证码、不爬登录后内容。
2. **合法合规**：遵守目标网站 robots.txt 与服务条款，控制请求频率（设置 `time.sleep` 间隔），不使用自动化手段绕过反爬。
3. **技术栈**：优先 `requests` + `BeautifulSoup`（或 `lxml`），必要时用 `pandas` 解析表格。
4. **产物**：爬取结果导出为 CSV/Excel，落入数据目录，并在数据来源说明中标注 `[外部]` + 网站名 + URL。
5. **脱敏**：对人名、联系方式、精确地址等敏感字段脱敏处理。

### Step 4：脚本造数据（仅知识库模式的优先级 2 / 联网模式的优先级 3）

前置判断：股票行情、经济统计、GIS 坐标等真实数据不适合脚本生成。联网模式下回退 Step 3；**仅知识库模式下无外部渠道可回退，标注「⚠️ KB无该数据集，需人工补充」，不阻塞流程**。

**Step 4a：Python 库自带数据（本地加载，两种模式均可用）** — sklearn、seaborn、statsmodels、akshare 等，代码加载后导出 CSV/Excel，来源标注 `[Python库]`。

适合生成：用户画像、订单流水、问卷、日志、学生成绩、商品信息等。按 `data_requirement` 的 fields 和 rows 生成。

**常识合规规则**（强制）：

造数据必须符合该行业的已知规律和公开统计结果，不得违背常识：

| 规则 | 示例 |
|------|------|
| 周期性规律 | 电商订单：618/双11/节假日订单量须明显攀升；春运期间出行数据须大幅上升 |
| 公开统计一致 | 汽车销量数据须与已发布的行业报告/新闻中的总量、品牌排名趋势一致 |
| 时序合理性 | 温度数据须符合季节变化；工作日/周末的客流须有明显差异 |
| 业务常识 | 退货率通常在 5%~15%；转化率通常在 1%~10%；不可出现全 0 或全满列 |
| 分布合理 | 金额、数量等数值列须有合理的均值、方差和离群值，不可全部均匀分布 |

> 若该领域存在已发布的行业报告、新闻统计结果，且 `资料来源模式=知识库+互联网`，造数据前须先 web_search 获取关键指标（如总量、均值、趋势），确保生成数据与之吻合；「仅知识库」模式下**禁止 web_search**，按模型内置常识与公开统计的一般规律执行，并在数据来源说明中注明「未经联网核验」。

## 合规检查

- 数据已存入目标路径，可正常读取
- 字段与 `data_requirement.fields` 一致
- 行数在 `data_requirement.rows` 范围内
- 数据来源可溯源
- 字段含单位（如"消费金额/元"）
- 不含敏感词（品牌名、人名、地名需脱敏）

---

## 约束

1. KB 优先：必须优先尝试 KB 拉取，不可跳过
2. **默认仅知识库，禁止联网**：未注入「资料来源模式=知识库+互联网」时，跳过外部数据集平台（A）与官网爬取（C），不得调用 web_search / 爬虫
3. P2 路径优先级（仅联网模式）：外部平台（A）> 官方网站爬取（C）> Python 库（B）
4. P3 前置判断强制：不适合生成的数据类型，联网模式回退 P2、仅知识库模式标注告警
5. 数据来源说明强制：完成后必须生成
6. 同一案例/示例使用同一数据集（章内独占，全书贯穿式章间共享）
7. 数据不含敏感词
8. KB 拉取失败静默降级，不阻塞
