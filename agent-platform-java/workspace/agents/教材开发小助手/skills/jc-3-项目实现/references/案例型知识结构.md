# 案例型知识结构

**适用场景**：案例分析、项目实现、综合应用、贯穿案例的章节

编写时的逻辑顺序，**不可颠倒**。

> **重要：以下①②③序号为写作框架指引，不是输出标题。** 各步骤根据当前 H3 主题，在有关键模块需要独立标识时使用 `####` 子标题（内容导向的标题，如"架构设计""逐步实现"），否则以自然段落展开。**禁止将框架步骤名（任务描述/方案设计/分步实现等）直接作为输出标题。**

根据案例性质，选择对应子类型。**判定方法**：案例的核心动作是"分析数据得出结论"还是"搭建系统产出成果"？

- 前者 → A. 数据分析类
- 后者 → B. 操作任务类

---

## A. 数据分析类

适用于数据挖掘、统计分析、机器学习建模等以数据为中心的案例。

### 内部编排结构

```
H2/H3标题
  ├─ ① 目标分析（必选）→ 案例背景 + 数据说明 + 分析目标 + 流程图
  ├─ ② 数据探索（必选）→ 读取→探索性分析（分析内容多则分类展开）
  ├─ ③ 数据处理（可选）→ 清洗→转换→特征工程（无需处理则跳过）
  ├─ ④ 建模/实现（必选）→ 基础知识（如基础篇未讲）→建模→调优
  └─ ⑤ 模型评价/结果应用（必选）→ 多模型放此处统一评价→最后写应用建议
```

**4项必选**（目标分析、数据探索、建模/实现、模型评价）+ **1项可选**（数据处理）。

### 各步骤内容要求

| 步骤          | 必/可选 | 内容                                         | 注意                             |
| ------------- | ------- | -------------------------------------------- | -------------------------------- |
| 目标分析      | 必选    | 案例背景 + 数据说明 + 分析目标 + 案例流程图  | 流程图须与案例内容对应           |
| 数据探索      | 必选    | 读取数据 + 各种探索性分析                    | 分析内容多时分类去分析           |
| 数据处理      | 可选    | 数据清洗、转换、特征工程                     | 无处理需求则跳过；方法无顺序之分 |
| 建模/实现     | 必选    | 如基础篇未介绍→先介绍基础知识→再建模→调优 | 先讲再练                         |
| 模型评价/应用 | 必选    | 多个模型统一放此处评价→最后写应用建议       | 有多个模型时必须比较             |

## B. 操作任务类

适用于 Coze 智能体搭建、Excel/Power BI 报表制作、软件配置部署等以操作为主线、最终产出可运行成果的案例。配图以 UI 截图为主，逐步配图。

### 内部编排结构

## 写作框架（框架描述，不是输出标题）

```
H2/H3标题
  ├─ ① 需求/背景说明：案例背景 + 需求分析 + 最终效果预览
  │     输出：根据主题概括为内容标题（如 #### 模块需求说明），或自然段落展开
  ├─ ② 方案/架构设计：整体架构/流程图 + 关键决策说明
  │     输出：内容标题（如 #### 整体架构设计）
  ├─ ③ 环境/前置准备：工具/平台 + 账号权限 + 素材/数据
  │     输出：内容标题（如 #### 开发环境准备）
  ├─ ④ 分步实现：逐步操作，每步：做了什么 → 为什么做 → 结果（逐步配图）
  │     输出：以 Step N 编号自然分隔（如 #### Step 1：编写接口代码）
  ├─ ⑤ 效果/结果验证：测试场景 + 运行结果 + 结果解释
  │     输出：内容标题（如 #### 运行验证）
  └─ ⑥ 本节回顾：关键决策回顾 + 踩坑/注意事项 + 拓展方向（可选）
        输出：内容标题（如 #### 本节要点）
```


### 各步骤内容要求

| 步骤     | 必/可选 | 内容                                                          | 注意                                     |
| -------- | ------- | ------------------------------------------------------------- | ---------------------------------------- |
| 任务描述 | 必选    | 案例背景 + 需求分析 + 最终效果预览（截图）                    | 让读者先看到"做成什么样"                |
| 方案设计 | 必选    | 整体架构/流程图 + 关键决策说明（为什么选这个工具/节点/方式）  | 流程图须与后续分步实现步骤一一对应       |
| 环境准备 | 必选    | 工具/平台清单 + 账号权限要求 + 素材/数据准备                  | 清单化呈现，读者对照准备                 |
| 分步实现 | 必选    | 逐步操作，每步：操作描述 → 操作目的 → 具体操作 → 配图        | 每步配图；步骤间承上启下（上一步输出 → 下一步输入） |
| 效果验证 | 必选    | 测试场景 + 运行/操作结果 + 结果解释                           | 至少 1 个测试场景验证核心功能            |
| 总结     | 必选    | 关键决策回顾 + 常见问题/注意事项 + 拓展方向（可选）           | 提炼可迁移的经验，不只重复做了什么       |

### 分步实现规则

1. **逐步配图**：每一步一个操作，配一张截图。关键界面（配置面板、运行结果、调试输出）必须配图
2. **承上启下**：当前步骤输入 = 上一步骤输出，写清楚衔接关系
3. UI 截图无现成来源时标记 `[待补齐]`（人工截取真实界面后替换）
4. 当来源仅提供步骤名称但无逐步 UI 交互细节时，严禁编造 UI 路径，标 `[待实测]`

## 三、案例模式适配

### 全书贯穿式

1. **同一主线**：分析类使用同一数据集、操作类使用同一项目，不可中途更换
2. **承上启下**：当前操作输入 = 上一步输出；当前章最终产出 = 下一章输入
3. **端到端闭环**：全书章节合在一起构成完整流程，中间不可断裂

### 综合案例式

> 前 M 章知识点+示例 + 后 K 章综合案例。项目任务式支持。

- **案例章不讲解知识点**：默认不包含知识准备，直接进入案例流程
- **例外**：前文**未涉及的进阶/额外知识点**，按知识类型规范插入讲解后再继续案例流程
- **理论章可附小示例**：理论章在知识准备后可用独立小节展示小示例演示，但非完整案例
