## 输入上下文

- **当前章摘要**：`artifacts/{教材}/第X章_{标题}/摘要/chapter_summary.json`（由 `jc-6-知识准备审核` 审核通过后提取产出，含术语/概念/符号）
- **当前章知识准备**：`artifacts/{教材}/第X章_{标题}/组件/知识准备_v{版本}.md`（AI 语义审核用）
- **已入库章节摘要**：所有已入库章节的 `摘要/chapter_summary.json`（对比基准）

> 一致性审核在知识准备审核通过后执行，当前章尚未拼装。`chapter_summary.json` 已前移至 `jc-6-知识准备审核` 审核通过后产出（仅覆盖知识准备组件），拼装后不再产出。当前章与已入库章节均以各自的 `chapter_summary.json` 为对比数据，Schema 一致可跨章解析。

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行方式

**自动化脚本 + AI 语义并列审核。脚本与AI独立运行，合并判定：任一方不通过即为整体不通过。**

### 第一步：运行自动化规则检查
```bash
python scripts/audit_consistency.py --target <当前章 chapter_summary.json> --prev <已入库章 chapter_summary.json>
```

**脚本输出**（stdout，结构化文本）：

| 检查项 | 说明 |
|--------|------|
| 概念定义差异 | 对比 JSON 中同名概念的 definition 字段，文字不同即标记（专有表述须逐字一致） |
| 术语拼写冲突 | 检测同一术语在不同章中的拼写/abbreviation/full_en 差异 |
| 符号含义冲突 | 检测同一符号在不同章中的含义不一致 |

> 「跨章重复」检测由 AI 语义审核完成（脚本侧不实现），见第二步第 4 项。

脚本独立输出审核结论（通过/不通过 + 检查项明细）。不产生任何持久化文件。

### 第二步：AI 语义审核
独立读取 JSON 摘要和正文内容，进行语义层面的对比，独立输出审核结论。

**1. 概念定义一致性**

- 同名概念的 `definition` 必须一致：**专有名词、专有表述、术语文字必须逐字一致**，不允许「表述不同但含义相同」——只要文字不同即判定不一致
- 同名概念的 `aliases` 是否存在冲突（不同章用不同别称指向同一概念）
- 核心定义是否有实质性偏差

**2. 术语命名一致性**

- 同一术语拼写、`abbreviation`、`full_en` 是否统一
- 描述风格相似的段落是否风格统一

**3. 符号一致性**

- 同一符号在不同章的含义是否一致
- 同一含义在不同章是否使用相同符号表示
- 符号 `type` 分类是否一致

**4. 跨章重复检查**

- 是否有同一知识点在多章正文展开（可引用但不可重复介绍）
- 概念首次出现时才介绍，后面章节可引用但不应重复定义

## 质量仲裁

| 本章质量 vs 已入库 | 决策 | 处理 |
| ------------------ | ---- | ---- |
| 本章更优 | 通过 + 建议回溯 | 本章入库，通知回溯修改已入库章节 |
| 持平 | 保留 | 本章入库 |
| 本章更差 | 驳回 | 退回对应体例Agent修改 |

### 第三步：合并判定

脚本与AI各自独立给出通过/不通过结论。**任一方不通过 → 整体不通过**。汇总双方所有不通过点，结合质量仲裁表给出最终裁决。

## 输出格式

```
[审核结果] 通过 / 建议回溯 / 不通过

## 脚本审核：[通过/不通过]
（脚本输出的检查项明细：通过项 + 不通过项）

## AI审核：[通过/不通过]
通过项：（列出所有AI通过的检查项）
不通过项：（每项注明具体位置、问题描述、修改建议）

质量对比结论：（本章更优 / 持平 / 更差）
裁决：（通过入库 / 通过+建议回溯 / 驳回重写）

[综合评定]
脚本与AI合并判定：双方均通过 → 整体通过；任一方不通过 → 整体不通过。
汇总双方所有不通过点与修改建议。
```
