## 输入上下文

- **前后置组件**：前言 / 内容提要 / 附录 / 参考文献
- **全书目录和内容**：供对比检查

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行方式

**自动化脚本 + AI 语义并列审核。脚本与AI独立运行，合并判定：任一方不通过即为整体不通过。**

### 第一步：运行自动化规则检查
```bash
python scripts/audit_front_back.py <待审核内容.md>
```

**脚本输出**（stdout，结构化文本）：

| 检查项 | 说明 |
|--------|------|
| 前言 | 检测前言节点存在性及子结构（行业背景/特色/适用对象/下载反馈/不含二十大） |
| 内容提要 | 检测内容提要节点存在性及适用对象说明 |
| 附录 | 检测附录节点存在性（非强制） |
| 参考文献 | 检测参考文献无博客来源、无脚注尾注 |

脚本独立输出审核结论（通过/不通过 + 检查项明细）。不产生任何持久化文件。

### 第二步：AI 语义审核
读取被审核文件实际内容，独立输出审核结论。

---

**1. 前言**

- 一段话引入：从行业背景、人才需求引入为什么要写这本书
- 本书特色：从内容设计角度编写，不罗列内容提要
- 适用对象：分点列出
- 代码下载信息：完整准确，注意核实数据/代码语言
- 正文中「二十大」三字不得出现

**2. 内容提要**

- 第1段：一句话写出本书内容设计上的特色 + 简洁概述主要内容
- 第2段：适用对象准确

**3. 附录**

- 补充知识点：文中提到但未详细阐述且重要的内容，或作为拓展升级信息
- 查询表：固定参数汇总（如函数汇总表，需包含本书介绍的）
- 名词解释：中英文解释，补充说明对目标读者较难理解的词

**4. 参考文献**

- 来源权威：论文、综述、专著等，不参考博客/百度知道/百度百科（可参考资料下属的参考文献）
- 文中不插入脚注或尾注，统一在全书后面另附一页
- 不能直接抄原文，需经理解后用通俗语句表述
- 编写过程中先记录，整书完成后统一整理

### 第三步：合并判定

脚本与AI各自独立给出通过/不通过结论。**任一方不通过 → 整体不通过**。汇总双方所有不通过点，统一输出。

## 输出格式

```
[审核结果] 通过 / 不通过

## 脚本审核：[通过/不通过]
（脚本输出的检查项明细：通过项 + 不通过项）

## AI审核：[通过/不通过]
通过项：（列出所有AI通过的检查项）
不通过项：（每项注明具体位置、问题描述、修改建议）

[综合评定]
脚本与AI合并判定：双方均通过 → 整体通过；任一方不通过 → 整体不通过。
汇总双方所有不通过点与修改建议。
```
