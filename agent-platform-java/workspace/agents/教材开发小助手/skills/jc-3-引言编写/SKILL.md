## 输入

| 参数 | 路径 |
|------|------|
| 目录结构.json | `artifacts/{教材名称}/章节目录/目录结构.json` |
| 知识概要.md | `artifacts/{教材名称}/章节目录/知识概要.md`（本章） |

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 规范

始终加载 `references/全局写作原则.md` + `用语与格式规范.md`。

## 体例输出格式

> 仅项目任务式体例有"引言"组件。项目式体例无引言（由【项目描述】替代，见 `jc-3-项目实现`）。

| 体例 | 输出组件 | 路径 | 结构 |
|------|----------|------|------|
| 项目任务式 | 【引言】 | `artifacts/{教材名称}/第X章_{标题}/引言.md` | 背景引入 + 章书关系 + 内容预览（3段，4~10行） |



## 工作流程

### Step 1：读取

读取目录结构.json（章标题、前后章关系）、知识概要.md（本章知识点概要）。

### Step 2：编写标准 3 段

| 段 | 内容 | 要求 |
|-----|------|------|
| 第1段：背景引入 | 由背景、由来、定位、作用等引入本章知识点 | 工具章：技术发展历程/热点/应用领域；案例章：行业整体发展状况，不描述案例具体情况 |
| 第2段：章书关系 | 本章与全书的关系 | 必须体现 |
| 第3段：内容预览 | 简略介绍本章主要知识点 | 1~2 行，不超过 3 行 |

总行数 4~10 行。标题间引言（H2↔H3、H3↔H4）起承上启下作用，无固定结构，视内容而定。

### Step 3：产出

生成引言 Markdown。

## 核心约束

1. 标准模式：3 段完整，4~10 行
2. 必须体现本章与全书的关系
3. 案例章引言不描述案例具体情况

## 修改模式

收到 `[修改指令]` 时：仅修改指出的问题点，逐条对照修正。
