## 输入上下文

- **知识图谱.json**：`artifacts/{教材名称}/章节目录/知识图谱.json`
- **知识图谱.md**：`artifacts/{教材名称}/章节目录/知识图谱.md`
- **教材定位**：核心知识点

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行方式

**自动化脚本 + AI 语义并列审核。脚本与AI独立运行，合并判定：任一方不通过即为整体不通过。**

### 第一步：运行自动化规则检查

```bash
python scripts/audit_knowledge_graph.py --json <知识图谱.json> --md <知识图谱.md>
```

**脚本输出**（stdout，结构化文本）：

| 检查项 | 说明 |
|--------|------|
| JSON 字段完整性 | 逐节点校验 id/name/difficulty/prerequisites/dependents 等必填字段 |
| 依赖循环检测 | 深度遍历依赖图，检测并标注循环环路 |
| 孤点检测 | 统计既无前置又无后置的非入口节点 |
| 入口统计 | 统计无前置节点数，与主题域数对比 |
| 难度分布 | 统计基础/进阶/高级 占比，基础占比是否 ≥ 30% |
| 难度值校验 | 检查难度值是否仅限 基础/进阶/高级 |
| 思政点校验 | 检查思政_points 中 target_knowledge 的 ID 是否存在、ID 是否重复 |
| 双格式一致性 | 逐字段对比 .md 与 .json 的知识点数量、id、name、difficulty、prerequisites、dependents、theme 等字段 |

> 知识点覆盖语义（核心知识点 vs 图谱知识点对应关系）和域结构合理性由第二步 AI 完成。

脚本独立输出审核结论（通过/不通过 + 检查项明细）。不产生任何持久化文件。

### 第二步：AI 语义审核

读取被审核文件实际内容，独立输出审核结论，按以下 6 个维度逐项审核，每项给出通过/不通过判定。

---

## 审核维度

### 1. 知识点覆盖

逐条核心知识点核对是否在知识图谱中有对应知识点：

- 每条核心知识点必须对应 ≥ 1 个图谱知识点。缺失则标注「核心知识点缺失」
- 图谱中与核心清单无关联且不可独立教学的知识点 → 标注「疑似多余」
- 子知识点不计入覆盖统计，仅父节点参与

### 2. 主题域结构

- 域内知识点数 3~8 个。不足 3 → 标注「域过碎，建议合并」；超过 8 → 标注「域过重，建议拆子域」
- 域间顺序是否由依赖链推导：域A内知识点是域B的前置 → 域A在域B前。违反则标注「域序异常」

### 3. 依赖关系

对每个知识点：

- **无循环**：从任意节点深度遍历不能回到自身。发现循环 → 标注具体环路
- **入口覆盖**：每个非入口节点至少 1 个前置。缺失则标注「无前置」
- **入口上限**：无前置节点数 ≤ 主题域数。超出则标注「入口过多」
- **域间依赖**：域A节点→域B节点 ⇒ 域A的 order < 域B的 order。违反则标注「域序与依赖冲突」
- **孤点检测**：某节点既无前置又无后置，且不属于入口节点集合 → 标注「疑似孤立」

### 4. 难度分布

- 难度值仅允许 基础 / 进阶 / 高级
- 基础知识点占比 ≥ 30%。不达标则标注「基础占比不足」

### 5. 思政融入

- `思政_points` 为知识图谱 **顶层字段**（与 `jc-1-知识图谱` 生成端 Schema 一致，位于 `themes` 之外），数组中每个思政点的 `target_knowledge` 必须在知识图谱中存在对应知识点 ID
- 思政点 ID 无重复

### 6. 双格式一致性

逐字段核对知识图谱.md 与知识图谱.json：

- 知识点数量一致（含子知识点）
- 每个知识点的 id、name、difficulty 完全一致
- 每个知识点的 prerequisites / dependents 列表一致
- 每个知识点的 case_direction 一致
- 每个知识点的 思政_point 一致
- theme 的 id、name、order 一致
- meta 字段一致

### 第三步：合并判定

脚本与AI各自独立给出通过/不通过结论。**任一方不通过 → 整体不通过**。汇总双方所有不通过点，统一输出。

## 输出格式

```
[审核结果] 通过 / 不通过

## 脚本审核：[通过/不通过]
（脚本输出的检查项明细：通过项 + 不通过项）

## AI审核：[通过/不通过]
通过项：（列出所有AI通过的检查项）
不通过项：（每项注明具体位置、问题描述、修改建议）

[综合评定]
脚本与AI合并判定：双方均通过 → 整体通过；任一方不通过 → 整体不通过。
汇总双方所有不通过点与修改建议。
FAIL 时建议退回 jc-1-知识图谱 修改后再审。
```
