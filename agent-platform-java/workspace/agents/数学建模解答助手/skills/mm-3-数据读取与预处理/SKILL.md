# 数据读取与预处理

## 原则

数据处理必须由题目契约、附件 schema 和已确认假设驱动。不得凭旧题记忆补列、补值、改单位或隐式下载数据；不得硬编码用户电脑绝对路径。

## 输入检查

生成代码前逐项核对：

- 输入文件相对路径、文件存在性和 `input_manifest`/SHA-256
- 必需列、主键、索引、数据类型、时间范围和时间步长
- 单位、数量级、正负号约定、边界和允许范围
- 缺失值、重复记录、重复时间戳、时间断裂和排序
- 多文件关联键、行数和覆盖范围

将文件路径、列、时间范围、时间步长、单位和缺失值策略登记到 `spec.json`。

## 预处理实现

- 读取、清洗、类型转换、单位换算、特征构造和输入校验拆成明确的小函数。
- 单位换算保留转换系数和来源，不能把存量、流量、速率或时间步长混用。
- 缺失值策略必须显式：拒绝、删除、插值、前向填充或模型内处理，并说明适用条件和影响。
- 时间序列禁止随机打乱；训练/验证按时间切分，缩放器和特征选择只在训练集拟合。
- 对索引唯一性、连续性、维度、数值有限性、非负/越界、数量级和覆盖范围执行检查。
- 检查失败应抛出带可操作提示的异常，并以非零退出码结束；不得捕获后继续产出看似有效的结果。

## 可追溯性

运行包必须说明：

- 实际读取的相对路径和输入 hash
- 处理后数据的字段、单位和行数
- 过滤、填充、换算和异常处理记录
- 特征窗口、训练窗口和预测索引（如适用）
- 输入变化会使哪些结果或回传标记为 `STALE`

用户运行后将校验报告写入 `results/validation.json`，代码阶段只检查是否实现了对应逻辑，不代用户运行。

## 禁止事项

- 绝对路径、`..` 路径、覆盖原始输入
- 隐式下载数据或依赖未登记的外部文件
- 用示例数据、随机数字或口述数据替代用户附件
- 使用未来数据、`random_split` 或对测试集执行拟合
- 静默修改单位、缺失值或异常值含义
