## 1. 方法库调用总协议

### 1.1 智能体必须先抽取的题目契约

在选择方法前，智能体必须将题目转成结构化契约，至少包括：

```yaml
problem_contract:
  objective: "预测 | 分类 | 排序 | 评价 | 优化 | 调度 | 分配 | 选址 | 仿真 | 解释因果 | 识别异常"
  decision_type: "静态 | 动态 | 多阶段 | 随机 | 鲁棒 | 对抗"
  entities: []
  decision_variables: []
  state_variables: []
  parameters: []
  constraints: []
  data:
    source: []
    granularity: "个体/日/小时/空间单元等"
    sample_size: null
    missingness: null
    noise_level: "低 | 中 | 高 | 未知"
  output_requirements: []
  evaluation_metric: []
  hard_requirements: []
  unknowns: []
```

### 1.2 方法选择输出格式

每次调用方法必须返回以下字段，不允许只返回方法名称：

```yaml
model_selection:
  primary_method_id: "M-xxx"
  backup_method_ids: ["M-xxx"]
  problem_fit: 0.0
  interpretability: 0.0
  data_fit: 0.0
  computational_fit: 0.0
  validation_plan: []
  key_assumptions: []
  known_risks: []
  reason_for_selection: ""
  disqualifying_conditions: []
  required_user_confirmations: []
```

评分范围为 0 到 1。`problem_fit` 和 `data_fit` 是硬门槛优先项；总分高不代表可以忽略不满足的硬约束。

### 1.3 选择顺序

1. 识别任务动词：预测、解释、优化、评价、分类、排序、仿真或识别。
2. 识别决策结构：是否有决策变量、目标函数、约束、时间演化、不确定性和竞争主体。
3. 建立最小可行模型：优先线性、可解释、可验证的模型。
4. 检查数据条件：样本量、变量类型、缺失、异常、时间泄漏、空间相关和测量误差。
5. 选择主模型与至少一个备选或基线模型。
6. 明确验证：误差指标、约束可行性、残差、稳定性、敏感性、外推风险。
7. 输出模型卡片、参数来源、结果证据和不可识别项。

### 1.4 方法组合规则

- **预测 + 决策**：先用预测模型产生参数或情景，再用优化模型决策；不得直接把预测值当成确定事实而省略不确定性。
- **评价 + 排序**：先定义指标和方向，再使用标准化、权重或降维方法，最后进行排序稳定性分析。
- **网络 + 优化**：先定义节点、边、容量、方向、成本和连通性，再选择最短路、流、匹配或选址模型。
- **时间序列 + 异常**：先建正常机制或预测区间，再用残差、控制图或变点方法判别异常。
- **仿真 + 优化**：仿真用于评价候选策略，优化器用于搜索；仿真输出必须报告随机种子、重复次数和置信区间。
- **机器学习 + 论文建模**：机器学习用于预测或近似，必须补充可解释性、基线、交叉验证和数据泄漏检查。

## 2. 方法卡片标准字段

每个方法条目使用以下属性：

| 字段 | 含义 |
|---|---|
| `method_id` | 稳定唯一标识，格式为 `M-领域-编号` |
| `name_zh / name_en` | 中英文名称 |
| `family` | 方法族 |
| `task_types` | 可解决的任务类型 |
| `problem_signature` | 题目中应出现的结构信号 |
| `core_idea` | 核心数学思想 |
| `mathematical_form` | 典型目标函数、方程或结构 |
| `inputs` | 必需输入 |
| `outputs` | 标准输出 |
| `assumptions` | 必须检查的假设 |
| `hard_constraints` | 不满足则禁用的条件 |
| `strengths` | 优点 |
| `limitations` | 局限 |
| `validation` | 验证方法 |
| `sensitivity` | 敏感性分析 |
| `complexity` | 计算复杂度或规模风险 |
| `selection_tags` | 供检索的标签 |
| `composable_with` | 推荐组合的方法 |
| `fallbacks` | 失败降级路线 |
| `agent_actions` | 智能体调用步骤 |

## 11. 统一验证协议

### 11.1 数据层

- 检查单位、量纲、时间粒度、空间粒度、主键和重复记录。
- 区分缺失、零值、截尾、删失和异常值。
- 时间序列禁止随机打乱造成未来信息泄漏。
- 训练/验证/测试划分必须写入方法卡片或运行配置。
- 任何外部数据必须记录来源、抓取时间、版本和字段映射。

### 11.2 数学层

- 每个变量写出定义、单位、取值域和决策属性。
- 目标方向统一为最小化或最大化；指标正负向明确。
- 检查约束可行性、守恒关系、概率和为 1、矩阵维度。
- 做无量纲化或尺度标准化，避免数值尺度支配结果。
- 对关键结论至少做一项参数敏感性和一项结构敏感性分析。

### 11.3 结果层

- 优化：报告可行性、目标值、gap、替代方案和瓶颈约束。
- 预测：报告基线、样本外误差、区间覆盖和分组误差。
- 评价：报告权重、排序稳定性、指标冗余和方向处理。
- 仿真：报告随机种子、预热期、重复次数、置信区间。
- 因果：报告识别假设、估计对象、安慰剂和敏感性。

### 11.4 失败降级原则

1. 数据不足：先减少模型复杂度，不补造数据。
2. 假设不满足：改用更弱假设的方法，或明确只能做描述性结论。
3. 精确求解超时：报告当前上下界，转分解/启发式，并保留基线。
4. 参数不可识别：减少参数、增加观测、设计实验或改为情景分析。
5. 验证不通过：模型状态标记为 `NOT_READY`，不得输出确定性结论。

## 12. 智能体方法卡片调用模板

```yaml
method_call:
  method_id: "M-OPT-001"
  problem_contract_ref: "problem_contract.json#/problem"
  user_goal: ""
  extracted_evidence:
    - text_span: ""
      signal: ""
  fit_check:
    satisfied: []
    violated: []
    unknown: []
  instantiation:
    variables: []
    objective: ""
    constraints: []
    parameters: []
  execution_plan:
    preprocessing: []
    solver_or_algorithm: ""
    stopping_rule: ""
    random_seed: null
  validation_plan:
    baseline: ""
    checks: []
    sensitivity: []
  return_schema:
    primary_outputs: []
    diagnostics: []
    evidence_files: []
  status: "PROPOSED | APPROVED | RUNNABLE | VALIDATED | REJECTED"
```

### 状态定义

- `PROPOSED`：智能体提出候选方法，尚未确认假设。
- `APPROVED`：用户或总控确认方法和关键假设。
- `RUNNABLE`：输入、参数和运行环境齐全，可生成代码/执行。
- `VALIDATED`：通过数据、数学、结果三层验证。
- `REJECTED`：硬约束不满足或验证失败，必须说明原因和替代方法。

## 13. 推荐的最小方法组合

| 题型 | 主模型 | 必须保留的基线/对照 | 核心验证 |
|---|---|---|---|
| 资源分配 | LP/MILP | 等比例或贪心方案 | 可行性、敏感性、gap |
| 多目标权衡 | Pareto/ε-约束 | 单目标方案 | 前沿稳定性、权衡解释 |
| 时间预测 | ARIMA/ETS/树模型 | 朴素法 | 滚动验证、区间覆盖 |
| 评价排序 | AHP/TOPSIS/熵权 | 等权 | 权重和标准化敏感性 |
| 设施选址 | 选址-分配 MILP | 贪心/聚类 | 覆盖、容量、情景 |
| 排队服务 | 离散事件仿真 | 排队论近似 | 重复仿真、置信区间 |
| 因果政策 | DID/RD/SCM | 描述性前后对比 | 识别假设、安慰剂 |
| 风险规划 | 鲁棒/情景/机会约束 | 名义优化 | 样本外违约率 |
| 异常检测 | 残差/控制图/孤立森林 | 固定阈值 | 误报、漏报、延迟 |

## 14. 智能体禁止事项

- 不得因为题目出现“最优”就自动使用遗传算法或线性规划。
- 不得把相关性描述为因果性。
- 不得在没有数据支持时虚构参数、概率分布、权重或样本量。
- 不得将一次启发式运行结果标为全局最优。
- 不得只报告拟合优度而不报告样本外验证。
- 不得省略单位、边界条件、随机种子、版本和输入来源。
- 不得把模型预测值未经不确定性处理直接送入后续优化并称为稳健方案。
- 不得用复杂模型掩盖题目结构不清、数据质量不足或识别假设不成立。

## 15. 版本与扩展约定

- 新方法必须分配唯一 `method_id`，不得复用旧 ID。
- 方法条目的数学形式、适用边界或验证要求发生重大变化时升级主版本。
- 增加同一方法的实现细节时升级次版本。
- 修正文字、链接或示例时升级补丁版本。
- 后续可扩展字段：`papers`、`software_support`、`solver_requirements`、`example_cases`、`failure_cases`、`evidence_level`。
- 推荐将本文件拆分为：`schema.md`、`methods/*.md`、`selection_rules.md`、`validation_protocol.md`，并建立索引文件供 RAG 或工具调用。

## 16. 权威性与使用声明

本方法库依据经典运筹学、统计学、时间序列、机器学习、图论、系统仿真、可靠性、空间统计和因果推断的通用建模范式整理。它是分析智能体的候选方法知识库，不替代具体题目的数据审查、领域专家判断和结果验证。对任何实际结论，必须保留题目契约、输入版本、模型假设、求解日志、验证证据和敏感性分析。
