# 机理识别与模型路线比较

## 方法库检索（先于逐问推导）

本 Skill 目录附带结构化**方法库**（35 张方法卡片 + 协议，运行时随 Skill 物化）。用 `glob_files(pattern="**/方法库/索引.md")` 定位后按文件工具读取：

| 文件 | 内容 |
|---|---|
| `方法库/索引.md` | 全部方法卡片总索引：method_id / 名称 / family / task_types / selection_tags |
| `方法库/<method_id>.md` | 单张卡片全文：核心思想、数学形式、假设、硬约束、优缺点、验证、敏感性、组合与降级 |
| `方法库/调用协议.md` | 方法选择输出格式（§1.2）、组合规则（§1.4）、决策树（§10）、统一验证协议（§11）、调用模板与状态定义（§12）、最小方法组合（§13）、禁止事项（§14） |

检索顺序：
1. 按 `调用协议.md` §10 决策树（预测/分类、优化/决策、评价/排序、网络/空间、仿真/风险、识别/诊断）得到候选 method_id 短名单；
2. 在 `方法库/索引.md` 上用 `grep_files` 按 selection_tags 或任务关键词过滤确认；
3. 打开命中的 2~3 张 `方法库/<method_id>.md` 读完整卡片，再进入下方逐问推导。

两条边界：
- 方法库是**候选清单，不是替换判断**——题目结构确实不匹配任何卡片时允许库外路线，但必须标注 `method_id: null（库外）` 并说明理由；禁止为套用卡片而扭曲题目结构。
- `调用协议.md` §1.1 的题目契约抽取**不要重复执行**——本流水线里它已由 `mm-1-子问题契约与依赖图` 产出的 `problem_contract.json` 承担，直接复用其字段。

## 步骤
1. 先判定任务是预测、解释、优化、评价、分类、仿真、判定或组合任务，再归纳支撑该任务的机制证据。
2. 仅在题目/数据支持时考虑守恒、动力学、扩散/传热、统计规律、几何、资源约束、因果、网络或经验关系等机制；不要为套模型而套机制。
3. 对每问至少给出一个候选路线，并从方法库为该路线登记 `method_id`；数据或机制不充分时，将其标为暂定并说明缺少何种证据。
4. 优先推荐可解释、参数可获得、能满足题目输出的最小可行模型；复杂模型作为有明确启用条件的备选——方法卡片的 `hard_constraints` 不满足时必须降级到其 `fallbacks`。
5. 每条路线记录输入、核心关系/目标/约束的文字表达、参数标定需求、求解步骤、适用边界、优缺点和主要风险；方法卡片的 `assumptions`/`validation`/`sensitivity` 字段可直接引用改写，不必另起炉灶。
6. 算法选择须服务于模型结构与规模；可解析求解时说明，数值/优化算法只给建议及停止/终止条件，不生成代码或结果。
7. 提出适配的评价指标、基线/对照及验证计划，指出需由求解或质检成员实际完成的工作；验证计划不得低于方法卡片 `validation` 字段与 `调用协议.md` §11 的要求。

## 输出与自检
输出 `solution_map`。在原有字段基础上，每条路线补充：

- `method_id`：方法库唯一标识（如 `M-OPT-001`）；库外路线填 `null（库外）`。
- `selection_summary`：按 `调用协议.md` §1.2 格式的精简版——`primary_method_id`、`backup_method_ids`、`problem_fit`、`data_fit`、`validation_plan`、`key_assumptions`、`known_risks`、`reason_for_selection`、`disqualifying_conditions`（评分为 0~1，`problem_fit` 与 `data_fit` 是硬门槛优先项）。

自检项：
- 路线逐问覆盖、符号与 problem_contract 一致，模型选择理由可追溯；
- 每条 `method_id` 都真实存在于 `方法库/索引.md`（防止编造 ID）；
- 主路线与备选路线的卡片 `hard_constraints` 均已逐条核对，未满足项已写明降级去向；
- 未违反 `调用协议.md` §14 禁止事项（不得见"最优"就上启发式/线性规划、不得把相关当因果、不得虚构参数/权重/分布等）；
- 禁止宣称算法已运行或路线已验证。
