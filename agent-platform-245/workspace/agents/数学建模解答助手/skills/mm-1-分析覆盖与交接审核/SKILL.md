# 分析覆盖与交接审核

## 检查清单
- 每个题面子问均有稳定 question_id、目标、输入、输出、约束和完成判据；无漏问/擅自扩题。
- 来源清单覆盖所有实际输入；事实有来源锚点；事实、推断、假设、未知状态没有混用。
- dependencies 引用有效问题 ID，依赖类型和理由明确。
- 假设、变量、参数、指标定义合理；符号不冲突，单位缺失有标记。
- 数据可用状态真实；未读附件、缺失数据和质量风险清楚；处理方案不伪装成已执行。
- 每个问题都有候选路线、推荐理由、数据需求、风险、评价/验证计划；没有臆造数值或声称验证通过。
- Markdown、problem_contract、solution_map、analysis_result 的 question_id、符号和路线一致；编码字符合法，JSON 语法可解析。
- 下游代码/论文交接信息足以行动；动画/可视化只出现接口引用，不生成相关资产。

## 处理失败项
严重缺题面、关键附件不可读或契约不可解析时将状态设为 BLOCKED；局部覆盖不足、非关键来源缺失时为 PARTIAL。列出每一失败项、影响和可执行的补全动作，不得以“自检通过”掩盖未执行检查。
