---
name: jc-6-目录审核
description: 审核目录智能体产出的章节目录和附录结构。检查整体结构合理性、知识点设置恰当性、案例合理性和体例合规性。在目录生成后调用。
---
## 输入上下文

- **目录智能体完整产出**：章节目录 + 附录结构 + 体例合规自检结果
- **用户指定的章节数**：目录生成时用户给出的目标章节数
- **体例模板**：`jc-1-目录生成/references/体例模板/{体例}.md`（下称"体例模板"）

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行方式

**自动化脚本 + AI 语义并列审核。脚本与AI独立运行，合并判定：任一方不通过即为整体不通过。**

### 第一步：运行自动化规则检查

```bash
python scripts/audit_toc.py --target <目录.md路径> --json <目录结构.json路径> --chapter-count <章节数>
```

**脚本输出**（stdout，结构化文本）：

| 检查项 | 说明 |
|--------|------|
| 章节数 | 与用户指定目标章节数对比 |
| 第一章概述 | 第一章是否为概述章 |
| 标题格式 | 按案例组织模式分支检测章标题格式（先导实战式/综合案例式/单章案例式/全书贯穿式） |
| 案例内容 | 无犯罪/死亡/传染病等消极词汇 |
| 工具/环境章 | 是否包含工具/环境章（非强制） |
| 附录结构 | 是否包含附录（非强制） |
| JSON 字段完整性 | 逐层校验顶层/章级/H2/H3/H4 必填字段 |
| 双格式一致性 | 逐章对比 .md 与 .json 的标题、编号、层级结构 |
| 体例模板一致性 | 对比目录 H2 组件与体例模板的名称、顺序 |

若 `--chapter-count` 为 0 或不传，跳过章节数校验。若 `--json` 不传，跳过 JSON 字段完整性及一致性检查。

脚本独立输出审核结论（通过/不通过 + 检查项明细）。不产生任何持久化文件。

### 第二步：AI 语义审核

读取被审核文件实际内容，独立输出审核结论，按以下 8 个维度逐项审核，每项给出通过/不通过判定。

---

**1. 整体结构**

- 是否总分结构：第一章是否为概述（介绍背景、发展、应用场景等），后续章节展开具体内容
- 是否有工具介绍部分：可放在第一章，也可单独成章

**2. 知识点设置**

- 难度是否匹配目标读者：不超纲，在目标人群理解能力范围内
- 覆盖是否全面：知识点能否完全覆盖书中案例涉及的知识点，可略超过案例范围作为拓展

**3. 案例设置**

- 案例选题是否实战向：非演示/理论验证式案例（如仅基于公开数据集+算法）
- 案例是否贴近生活/生产/科技应用场景，且内容积极向上
- 案例章节是否按由简到繁排列，遵循由浅入深
- **概述/工具章豁免**：概述章或工具介绍章无案例，自动跳过本项

**4. 章节内容量**

- 是否无内容堆砌或过少
- 各章知识点数量是否均匀

**5. 标题格式合规（强制）**

按案例组织模式分支执行，只查对应分支。**任意一项不通过即不通过**。

- **先导实战式**：所有章标题为纯知识主题名（不含案例名、不含 `——`），无独立案例章
- **综合案例式**：前N章标题为纯知识主题名（不含 `——`）；后1-2章标题格式为 `第X章 案例实战：XX案例名称`，案例名互不重复
- **单章案例式**：每章标题含 `——`（左侧知识主题 + 右侧案例名），案例名体现应用方向
- **全书贯穿式**：每章标题含 `——`（右侧体现案例执行阶段），各阶段无跳过、全流程闭环

**6. 体例模板结构一致性（强制）**

核对目录每章的 H2 组件与体例模板是否一致。**模板路径**：`jc-1-目录生成/references/体例模板/{体例}.md`。

审核步骤：

1. 读取目录产出中的 `【体例类型】`，加载对应 body 模板
2. 对照目录中每章的 H2 组件——**名称、顺序**必须与模板严格一致
3. 模板中 `(X.1…X.N)` 为可变数量节点，确认存在即可，不校验数量

审核规则：

- 组件**不可缺失**：模板中定义的组件须全部出现
- 组件**顺序不可颠倒**：必须与模板自上而下顺序一致
- 组件**不可多余**：不应出现该体例未定义的组件（如项目式不应出现「引言」）

**7. JSON字段完整性**

检查 `目录结构.json` 中各级字段是否齐全、且无多余字段。

审核步骤：

1. 读取 `目录结构.json`，逐层校验必填字段
2. 对比 jc-1-目录生成 SKILL.md 中定义的模板，检测是否存在模板未声明的多余字段

审核规则：

- **字段口径以生成侧为准**：`jc-1-目录生成` 的 Schema 是权威定义（含课时字段名 `periods`），本维度只核对这些必填字段是否齐全，不另立一套字段名
- **顶层字段**：必须包含 `目标读者`、`体例类型`、`案例组织模式`、`思政_required`、`chapters`
- **章级字段**：每章必须包含 `id`、`title`、`chapter_type`、`os`、`tools`、`periods`、`children2`
- **H2 级字段**：每个 H2 节点必须包含 `id`、`name`；如有下级则含 `children3`
- **H3/H4 级字段**：每个节点必须包含 `id`、`name`；如有下级则含 `childrenN`
- 任意必填字段缺失 → 不通过
- **允许的附加字段**：`version`、`generated_at`（版本号与生成日期，jc-1 模板自带）、`教材名称`、`总课时`、`chapter_no` 均不计为多余字段；此外模板未声明的字段 → 不通过

chapter_type 合法取值：理论类 | 案例类 | 操作类

**8. 目录.md与目录结构.json一致性**

检查两个文件内容是否一致。

审核步骤：

1. 同时读取 `目录.md` 和 `目录结构.json`
2. 逐章对比标题、编号和层级结构

> **比对口径（避免把渲染差异误判为不一致）**：
>
> - **按章块比对**：章级标题与各章 H2 组件逐章对比；文档级标题（`# 目录`、`## 全书概览`）与尾部「审阅辅助表」不属于任何章，不参与比对。
> - **H2 组件严格比对**：每章 H2 组件的名称集合与顺序必须与 JSON 的 `children2` 逐项一致（多、缺、乱序均不通过）。
> - **深层节点按渲染形态比对**：JSON 的深层节点在 md 中既可能渲染为标题（`### 【任务描述】`、`#### A-01 …`），也可能渲染为有序列表项（教学目标三项、实训/习题子项、任务实现步骤），**两种形态都算命中**；JSON 把编号与名称分列（`id="A-01"` + `name="Python 程序与运行方式"`），md 有的层级渲染编号、有的不渲染，两种写法都算命中。
> - md 侧额外渲染出 JSON 未建模的细粒度条目（如知识点下的具体写法）**不算不一致**；缺项或次序颠倒才算。

审核规则：

- **章节数一致**：两个文件中的章数必须相等
- **章节标题一致**：每章的标题文本必须对应
- **H2 标题一致**：每个 H2 的编号和名称必须对应
- **H3 标题一致**：每个 H3 的编号和名称必须对应
- **H4 标题一致**：每个 H4 的编号和名称必须对应
- 任意一项不一致即不通过

### 第三步：合并判定

脚本与AI各自独立给出通过/不通过结论。**任一方不通过 → 整体不通过**。汇总双方所有不通过点，统一输出。

## 输出格式

```
[审核结果] 通过 / 不通过

## 脚本审核：[通过/不通过]
（脚本输出的检查项明细：通过项 + 不通过项）

## AI审核：[通过/不通过]
通过项：（列出所有AI通过的检查项）
不通过项：（每项注明具体位置、问题描述、修改建议）

[综合评定]
脚本与AI合并判定：双方均通过 → 整体通过；任一方不通过 → 整体不通过。
汇总双方所有不通过点与修改建议。
```
