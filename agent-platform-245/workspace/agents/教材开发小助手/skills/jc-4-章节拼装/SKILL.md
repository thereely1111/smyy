## 输入上下文

- **组件清单**：jc-3 系列 skill 产出的所有组件（教学目标、知识准备、项目实现、小结、实训、课后习题、思维导图、引言、阅读拓展等）
- **体例类型**：`目录结构.json` 顶层字段「体例类型」（项目式 / 项目任务式，决定拼装顺序）
- **章节目录**：当前章节的标题和编号（`目录结构.json`）
- **体例模板**：`jc-1-目录生成/references/体例模板/` 中对应模板（组件顺序与名称的权威来源）

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 拼装顺序（按体例）

> 最新体例仅两种：项目式、项目任务式。组件顺序与名称严格遵循 `jc-1-目录生成/references/体例模板/` 中对应模板的组件树。

| 体例       | 组件拼装顺序                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 项目式     | 教学目标 → 项目描述 → 思维导图 → 知识准备 → 项目实施 → 项目小结 → 实训 → 课后习题 → 阅读拓展                                             |
| 项目任务式 | 引言 → 教学目标 → 思维导图 → 任务X.1（任务描述 → 知识准备 → 任务实现）→ 任务X.2（…）→ … → 项目小结 → 实训 → 课后习题 → 阅读拓展 |

> 项目任务式的每个「任务X.N」为 H2 级标题，其内部结构固定为【任务描述】→【知识准备】（含 X.N.1/X.N.2 等 H3 知识点）→【任务实现】。

## 执行操作

1. **组件完整性检查（强制）**：对照「组件 ↔ skill 产出对照」和当前体例的拼装顺序，检查所需组件是否齐全：

   - 缺失组件 → **不在此补写**，退回对应 jc-3 skill 生成（如缺引言 → jc-3-引言编写，缺实训 → jc-3-实训生成）
   - 思政未开启（`思政_required=false`）时，阅读拓展组件不强制（jc-3-阅读拓展 本就不产出）
2. **章节标题**：添加章节编号和章节名（按体例格式）
3. **组件排序**：按体例顺序排列各组件，最终结构和顺序与目录一致
4. **编号统一**：

   - 图号：图X-1、图X-2……（X为章号）
   - 表号：表X-1、表X-2……
   - 代码号：代码X-1、代码X-2……
   - 公式号：（X-1）、（X-2）……
5. **衔接段落**：组件间添加过渡语句，保证整章阅读流畅
6. **格式统一**：标题样式、题注格式、表格样式与样章模板一致
7. **题注与交叉引用检查（强制）**：遍历全文中所有图、表、代码，参照 `references/题注与编号规范.md` 规范，确保：

   - 每条题注在正文中有**至少一条提前引用句**（如图X-N所示/如表X-N所示/如代码X-N所示），引用句必须紧邻对应的图/表/代码之前
   - 缺失引用的，**不在此补充**，退回该图/表/代码所属组件对应的 jc-3 skill 修复（图/表/代码可能来自知识准备、项目实现、实训、课后习题等任一组件）
   - 表题注位于表格上方，图题注位于图下方，代码题注位于代码上方
   - 所有题注在 Word 中居中加粗（由 `jc-4-md转word` 脚本自动保证）
8. **待补齐图片处理（强制）**：

   - 识别图片 alt 文本中的 `[待补齐]` 标记
   - 保留 `[待补齐]` 标签在 alt 文本中，格式：`![图X-N 描述[待补齐]](图片/...)`
   - 引用句保持干净，不标注"待补齐"（如 `...如图1-1所示。`）
   - **禁止**为待补齐图片添加 ⚠️ 说明文字（如"注意：图X-X为...截图，请读者对照操作"）
   - **禁止**将 `[待补齐]` 从 alt 文本中移除
9. **输出净化（强制）**：拼装完成后必须遍历全文，删除以下面向学生教材中不应出现的内部元数据：

   - `难度：` / `知识点：` / `思政融入：` 等标注行及其后面的编码
   - `[来源]` 块及其全部内容（包括 `[来源]` 为行首标记的整个段落）
   - `[图片文件不存在: ...]` 等脚本错误信息
   - `[BLOCKED]` / `[资料缺失]` / `[待补充]` 等流程控制标记
   - ⚠️ `[待补齐]` 属于有效标记，**不可删除**
   - 版本号元数据行（如 `> 版本: v1.0`）
   - 所有 HTML 注释（`<!-- ... -->`）
   - `（参考资料：...）` 标注

## 约束

1. 不修改组件内容，只做拼装和衔接
2. 按顺序排列各组件，最终结构和顺序与目录一致
3. 格式与样章模板完全一致
4. 编号连续无跳号
5. **组件标题不加序号，保留组件原有编号**：组件一级标题（H2）与章节目录保持一致：
   - 项目式：`## 教学目标`、`## 项目描述`、`## 思维导图`、`## 知识准备`、`## 项目实施`、`## 项目小结`、`## 实训`、`## 课后习题`、`## 阅读拓展`
   - 项目任务式：`## 引言`、`## 教学目标`、`## 思维导图`、`## 任务X.1`（含任务描述/知识准备/任务实现）、`## 项目小结`、`## 实训`、`## 课后习题`、`## 阅读拓展`
   - 不得擅自为组件标题添加"一、二、三"等中文序号前缀。组件内部自带的小节编号（如知识准备中的 X.1、X.2）原样保留不做修改
6. **输出净化**：最终交付的 .md 文件和 .docx 文件中，不得出现以下内部元数据：
   - `> 难度：` / `> 知识点：` / `> 思政融入：` 等内部追踪标注
   - `[来源]` 块及全部内容
   - `[BLOCKED]` / `[图片文件不存在]` / `[资料缺失]` / `[待补充]` 等流程控制或错误信息
   - 版本号行（如 `> 版本: v1.x`）
   - HTML 注释、参考资料标注
7. **组件标题与 X.X 同级（强制）**：组件标题（教学目标/项目描述/思维导图/知识准备/项目实施/项目小结/实训/课后习题/阅读拓展）与 X.X 节标题**均用 `## `（二级）**，两者都保留、都不得删除。**禁止**因「组件标题与 X.X 平级」而删除 X.X 节标题（如 `## 2.4`）。
8. **组件内部标题层级原样保留（强制）**：拼装时**不得增减组件内部任何 `#` 数量、不得偏移标题层级**。目录结构.json 的 `children2` → `##`、`children3` → `###`、`children4` → `####`，拼装仅做组件排序与衔接，不重设层级。
9. **代码块内容原样保留（强制）**：``` 代码块内的所有内容（含 `#`/`##`/`###` 开头的行）必须原样保留在代码块中，**不得解析为标题**。围栏完整，不泄漏到正文。

## 修改模式

当收到 [修改指令] 时：

1. 仅修改反馈中指出的问题点，其余内容保持原样不变
2. 逐条对照 [修改指令] 中"审核反馈"列表逐一修正
3. 修正后输出完整内容（含未修改部分），不输出其他解释
