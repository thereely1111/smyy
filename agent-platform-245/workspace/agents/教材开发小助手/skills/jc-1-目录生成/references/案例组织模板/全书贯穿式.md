# 全书贯穿式 — 全书一个案例贯穿

适用：项目式

## 骨架结构

- 全书共享一个案例，每章对应一个执行阶段（章节=案例阶段）
- 章节类型分布：全部 `案例类`
- 阶段链 = 知识依赖链，各阶段不可跳过，全流程闭环

## 标题格式

| 体例     | 格式                                  | 示例                                   |
| -------- | ------------------------------------- | -------------------------------------- |
| 项目式   | `项目X XX知识主题——案例阶段N描述` | 项目3 数据预处理——电商数据清洗与转换 |

> 仅项目式支持全书贯穿式。

## 案例规则

- 全书共用一个案例，每章对应一个执行阶段
- 流程阶段链由知识图谱的依赖链决定（如数据采集→清洗→分析→可视化），各阶段不可跳过，全流程闭环
- 章节顺序 = 知识点依赖顺序 = 案例流程推进顺序
- 案例检索：全书统一检索，全书知识点整体匹配（不按单章筛选）
- 同案例各章阶段不重叠
- 若 KB 无主候选，AI 推断案例，case_source = "AI"
- 【强制留痕】无论处置为何，必须输出「命中案例 ↔ 全书知识点」覆盖对照表 + 覆盖率数值，写入案例清单
- 每章阶段章的知识讲解配必要示例：抽象/操作/易混/后文阶段依赖的知识点必配，简单概念可不配（遵循"示例必配原则"）

## 调度策略

N章严格串行（后章依赖前章案例产出+代码结果）。

> 案例清单须体现「章 ↔ 案例阶段 ↔ 命中案例切片 ↔ 数据流转」的显式映射（`chapter_id` 数组、`stages[].chapter_id`/`kb_part`、`data_flow[]`），字段结构见 `SKILL.md` 案例清单 Schema。
