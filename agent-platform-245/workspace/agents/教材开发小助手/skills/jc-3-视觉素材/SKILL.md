## 素材路由

| 类型         | 工具                                              | 输出标记                   | 处理方式                                                                                          |
| ------------ | ------------------------------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------- |
| `AI生图`   | `image_gen`                                     | 无标记                     | AI 生成概念示意图、原理图                                                                         |

## 一、AI生图

遍历 `@图片清单` 中 `类型: AI生图` 的条目。

### 步骤

1. 从条目提取 `描述` 和 `内容` 字段
2. 将 `内容` 填入下方 Prompt 模板的 `{内容描述}` 占位符，拼接完整 prompt
3. 调用 `image_gen`：`size="1536x1024"`，`quality="high"`，`output_dir={输出目录}`
4. 将生成文件重命名为 `图{章节编号}-{图号} {描述}.png`
5. 记录引用行：`![图{章节编号}-{图号} {描述}](图片/图{章节编号}-{图号} {描述}.png)`

### Prompt 模板

`{内容描述}` 取自 `@图片清单` 条目的 `内容` 字段。

```
{内容描述}的示意图，用于教材插图：
- 使用文本框、圆角框、箭头、连线等元素清晰表达结构或关系
- 抽象概念可用类比场景或直观图形辅助理解，关键节点配简短标签
- 布局清晰，主次分明
- 风格：专业学术风格，配色简洁，白色背景
- 无水印，无个人标识
- 图片内部不显示任何图号（如图1-1）或题注文字，题注由外部标注
```

### 约束

- 不生成软件界面截图
- 图片文件名与题注编号严格一致
- 生成的图片不做二次修改

## 二、代码生图

遍历 `@图片清单` 中 `类型: 代码生图` 的条目。

### 环境就绪

```bash
python scripts/install.py
```

### 步骤

1. 从条目提取 `图号`、`描述`、`内容` 字段
2. `内容` 中若为结构化节点列表 → 构建 JSON 调用；若为简单链式文本（如 A→B→C）→ 用 `--text` 调用
3. 输出文件名：`图{章节编号}-{图号} {描述}.png`
4. 记录引用行

### 调用方式

```bash
# JSON 结构化描述
python scripts/generate_diagram.py \
  --input diagram.json \
  --output "{输出目录}/图X-N {描述}.png"

# 简单文本描述
python scripts/generate_diagram.py \
  --text "{内容}" \
  --output "{输出目录}/图X-N {描述}.png"
```

### JSON 输入格式

详见 `scripts/generate_diagram.py` docstring。核心字段：

| 字段          | 类型 | 说明                                                   |
| ------------- | ---- | ------------------------------------------------------ |
| `direction` | str  | 布局方向，`TB`（竖向）或 `LR`（横向），默认 `TB` |
| `nodes`     | list | `{id, label, shape, type}`                           |
| `edges`     | list | `{from, to, label}`                                  |

`shape` 可选：`box` / `rounded` / `diamond` / `ellipse` / `cylinder`
`type` 可选：`start` / `process` / `decision` / `end` / `data`（控制配色）

## 三、待补齐占位

遍历 `@图片清单` 中所有 `类型: 待补齐` 条目（UI 截图等需人工截取的界面图）。

### 处理

无需生成或下载任何文件。引用行保持占位格式：

```markdown
![图X-N 描述[待补齐]](@TODO)
```

`[待补齐]` 标记表明此图需人工截取真实界面后替换。

---

## 输出

批量处理完成后，返回 `@图片结果` YAML：

```yaml
@图片结果:
  # AI生图 / 代码生图
  - 图号: "1-1"
    结果: ok
    引用: "![图1-1 AI-ML-DL关系图](图片/图1-1 AI-ML-DL关系图.png)"
  # 待补齐 → 占位
  - 图号: "1-4"
    结果: placeholder
    引用: "![图1-4 Trae安装向导界面[待补齐]](@TODO)"
```

Agent 据此将正文中对应图号的 `![图X-N 描述](@TODO)` 替换为实际引用行。

## 约束

- 图片文件名与题注编号严格一致，连续递进
- 三类条目全部处理，不可跳过任何类型
- 一次调用处理全部清单，不逐项调度
- `待补齐` 条目直接占位，不下载、不阻塞
