## 输入上下文

- **课后习题组件**：课后习题（选择题 / 填空题 / 操作题）
- **章节目录**：当前章节标题树
- **正文内容**：供对比覆盖度和超纲检查

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行方式

**自动化脚本 + AI 语义并列审核。脚本与AI独立运行，合并判定：任一方不通过即为整体不通过。**

### 第一步：运行自动化规则检查
```bash
python scripts/audit_concept_test.py <待审核内容.md>
```

**脚本输出**（stdout，结构化文本）：

| 检查项 | 说明 |
|--------|------|
| 选择题数量 | 检测选择题条目数，≥5 题 |
| 选项格式 | 检测 A./B./C./D. 格式一致性 |
| 多选题标记 | 检测多选题是否标注【多选题】 |
| 题干句号 | 检测题干末尾句号 |
| 括号空格 | 检测括号内是否含4个全角空格 |

脚本独立输出审核结论（通过/不通过 + 检查项明细）。不产生任何持久化文件。

### 第二步：AI 语义审核
读取被审核文件实际内容，结合正文进行对比，独立输出审核结论。

---

**1. 题数与覆盖**

- 选择题 ≥ 5 题（一般一个二级标题有 2 题以上，题数以本章知识点多少为依据）
- 操作题 ≥ 2 题（第1题基础操作，第2题综合，由简到难）
- 填空题（如有）：可选题型
- 是否覆盖每个二级标题的知识点（"至少覆盖二级标题的知识点"）
- 习题尽量覆盖每个三级标题的内容

**2. 内容质量**

- 内容不超纲，答案在本章正文中可找到
- 主要考察：概念、易混淆的函数/方法、不同函数/方法的使用、不同方法的区别
- 干扰项设计是否合理（不得过于明显或随意）

**3. 格式规范**

- 选项格式是否统一（A./B./C./D.）
- 括号内是否空 4 格全角空格
- 多选题是否标注【多选题】
- 题干是否以句号结尾

### 第三步：合并判定

脚本与AI各自独立给出通过/不通过结论。**任一方不通过 → 整体不通过**。汇总双方所有不通过点，统一输出。

## 输出格式

```
[审核结果] 通过 / 不通过

## 脚本审核：[通过/不通过]
（脚本输出的检查项明细：通过项 + 不通过项）

## AI审核：[通过/不通过]
通过项：（列出所有AI通过的检查项）
不通过项：（每项注明具体位置、问题描述、修改建议）

[综合评定]
脚本与AI合并判定：双方均通过 → 整体通过；任一方不通过 → 整体不通过。
汇总双方所有不通过点与修改建议。
```
