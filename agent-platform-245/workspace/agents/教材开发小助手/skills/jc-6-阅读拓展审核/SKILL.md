## 输入上下文

- **阅读拓展组件**：`阅读拓展.md`（导读 + 思考题）
- **章节目录**：当前章节标题树（技术方向）
- **正文内容**：供对比导读与本章技术结合度

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行方式

**自动化脚本 + AI 语义并列审核。脚本与AI独立运行，合并判定：任一方不通过即为整体不通过。**

### 第一步：运行自动化规则检查
```bash
python scripts/audit_reading.py --target <阅读拓展.md路径> [--sizheng on|off]
```

`--sizheng` 取 `目录结构.json` 的 `思政_required`（`true` → `on`，`false` → `off`），默认 `on`。
思政关闭时「思政元素融入」判据不参与判定（报告里列为「已跳过」），不再按缺思政硬判不通过。

**脚本输出**（stdout，结构化文本）：

| 检查项 | 说明 |
|--------|------|
| 结构 | 导读 + 思考题 两部分存在性 |
| 思政关键词 | 检测政府报告/思政相关关键词（`--sizheng off` 时跳过） |
| 思考题 | 检测思考题条目 |
| 敏感词 | 敏感词扫描（仅正文散文；代码围栏、行内码与围栏化运行结果不参与） |
| 模糊时间词 | 模糊时间表述扫描（同上，仅正文散文） |

脚本独立输出审核结论（通过/不通过 + 检查项明细）。不产生任何持久化文件。

### 第二步：AI 语义审核
读取被审核文件实际内容，独立输出审核结论。

**1. 导读质量**

- 导读是否与本章技术方向紧密结合（科普本章相关前沿技术）
- 是否体现思政（引导读者树立正确思想、走正确道路）
- 思政元素引出是否自然、不生硬
- 素材是否优先国产内容

**2. 思政原文引用合规（硬约束）**

- 引用政府报告（"十五五"规划、二十大报告等）原文时，是否一字不漏、一个符号不改
- 是否对引用的思政原文进行了解读（禁止解读）
- 思政元素是否与本章技术相关、不脱节
- 各章阅读拓展思政元素是否重复（跨章对比）

**3. 思考题**

- 思考题是否与导读或本章技术结合，不脱节

### 第三步：合并判定

脚本与AI各自独立给出通过/不通过结论。**任一方不通过 → 整体不通过**。汇总双方所有不通过点，统一输出。

## 输出格式

```
[审核结果] 通过 / 不通过

## 脚本审核：[通过/不通过]
（脚本输出的检查项明细：通过项 + 不通过项）

## AI审核：[通过/不通过]
通过项：（列出所有AI通过的检查项）
不通过项：（每项注明具体位置、问题描述、修改建议）

[综合评定]
脚本与AI合并判定：双方均通过 → 整体通过；任一方不通过 → 整体不通过。
汇总双方所有不通过点与修改建议。
```

## 修改模式

收到 `[修改指令]` 时：仅对反馈涉及的问题点重新审核，其余已通过项保持结论不变。
