## 选题原则

### 覆盖范围

- 尽量覆盖每个三级标题的内容
- 至少覆盖每个二级标题的知识点
- 内容不能超纲，答案必须能在正文中找到

### 选题禁区

- **不考查纯历史背景类知识**：如"某论文发表于哪一年""某技术源于哪篇论文""某项目哪年创建"等，选择题和填空题均不采用
- 不考查与本章技术核心无关的细枝末节
- 不考查文中没有明确说明的内容

### 选择题考查重点

- 核心概念的定义与辨析
- 不同函数/方法的区别与适用场景
- 易混淆的概念对比（如 Minor Compaction vs Major Compaction）
- 流程/步骤的顺序（如读写流程的查找顺序）
- 组件职责与功能定位

### 填空题考查重点

- 核心术语和缩写的全称
- 关键数量信息（如"四个维度""三种原则"等涉及数量的填空）
- 流程步骤中的关键节点名称
- 分类/类型的名称

### 操作题分层设计

| 层次 | 复杂度 | 涉及知识点数 | 示例                                 |
| ---- | ------ | ------------ | ------------------------------------ |
| 基础 | 简单   | 1个三级标题  | 使用 HBase Shell 创建预分区表        |
| 综合 | 中等   | 2~3个知识点  | 设计完整的表结构（行键+列族+预分区） |

## 题干编写规范

- **题目编号**：使用 `（1）（2）（3）` 格式，不使用 `1. 2. 3.` 或 `① ② ③`
- **选择题题干**：使用括号填空格式，不用疑问句，如 `（1）（    ）不属于HBase的核心特点。`
- **多选题标记**：题目开头加 `【多选题】`，仅标记一次
- **选项格式**：使用 `A．B．C．D．` 大写字母编号（全角点）
- **无需引导语**：每个题型下直接列出题目，不写"本部分共X题……"等说明性文字
- **填空题下划线**：下划线与前后文字之间不留空格，如 `HBase数据模型由________、________五个核心概念构成。`
- **操作题描述**：给出完整场景描述和数据说明（已知条件、查询需求、设计要求），子任务用 `（1）（2）（3）` 分点列出

## 工作流程

### Step 1：读取

读取目录结构.json（章节结构、知识点分布）、知识准备内容、项目实现内容（完整正文知识点）。

### Step 2：编写选择题

| 规范   | 要求                                                                   |
| ------ | ---------------------------------------------------------------------- |
| 题数   | ≥5题                                                                  |
| 覆盖   | 每个二级标题≥2题                                                      |
| 题干   | 括号填空格式，不用疑问句，如`（1）（    ）不属于……。`（括号空4格） |
| 选项   | `A．B．C．D．` 大写字母编号（全角点）                                |
| 多选题 | 题目开头加"【多选题】"，仅标记一次                                     |
| 题号   | 全章连续编号                                                           |
| 考点   | 概念辨析、方法区别、易混淆对比、流程顺序、组件职责                     |
| 干扰项 | 来自正文易混淆概念，有迷惑性                                           |

### Step 3：编写填空题

| 规范 | 要求                                            |
| ---- | ----------------------------------------------- |
| 题数 | ≥5题，每个二级标题≥1题                        |
| 空位 | 用`______` 占位，下划线与前后文字之间不留空格 |
| 考点 | 核心术语全称、关键数量、流程节点、分类名称      |

### Step 4：编写操作题

| 规范 | 要求                                                                         |
| ---- | ---------------------------------------------------------------------------- |
| 题数 | ≥2题，由简到难                                                              |
| 分层 | 第1题基础（1个三级标题知识点），第2题综合（2~3个知识点）                     |
| 描述 | 完整场景描述+数据说明，子任务用`（1）（2）（3）` 分点                      |
| 内容 | 直接列出操作要求，不得与正文已有操作重复                                     |
| 数据 | 需"贴近生活的新场景"数据时现场生成 data_requirement 并直接调用 jc-2-数据准备 |

### Step 4.5：数据需求判断

编写操作题时，判断该题是否需要数据：

- **需造新数据**：当操作题需要"贴近生活的新场景"数据时，现场生成一份 `data_requirement`（`data_types` + `fields` + `rows` + `说明`），通过**调用 jc-2-数据准备**，传入该需求，由其按三级优先级准备数据。

### Step 5：编写答案

所有题目写完后以 `【答案】` 隔开。答案与解析格式：

- 选择题：逐题给答案 + 解析，解析注明对应小节位置（如"参见4.2.1小节"），全文统一
- 填空题：给答案
- 操作题：给参考解答（含完整代码/命令 + 必要文字解释 + 分步骤说明），不能只给代码路径

**操作题代码与数据存放**：操作题的参考代码和数据统一存放到 `artifacts/{教材名称}/第X章_{标题}/习题答案/操作题N/`（N 为操作题编号，如操作题1、操作题2），代码文件和所用数据文件同目录存放，不区分代码/、数据/ 子层。

### Step 6：产出

生成课后习题 Markdown。

## 核心约束

1. 题数满足最低要求（选择题≥5题、填空≥5题、操作≥2题；选择题每二级标题≥2题）
2. 内容不超纲，答案在正文中可找到，不考历史背景类知识
3. 操作题不得与正文已有操作重复
4. 所有题目后必须有【答案】和解析
5. 题干用括号填空格式，不用疑问句；编号用 `（1）（2）` 格式；题型下不加引导语

## 修改模式

收到 `[修改指令]` 时：仅修改指出的问题点，逐条对照修正。
