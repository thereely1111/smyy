# jc-0-路径工具

教材编写系统路径约定的**唯一权威来源**。任何子智能体在拼写路径、写汇报前，必须先按本 Skill 执行。其它文件（AGENTS.md、各子智能体定义、各 Skill）一律**引用本文，不得复制其规则**。

## 背景（为什么是这样）

模型运行在框架（AgentScope Harness）的本地文件系统之上：平台把可写根设为**运行态根**（`runtimes/{agentId}`），并按**会话**加命名空间——每个会话（主编会话 `main-…`、每个子智能体会话 `sub-…`）的**相对路径都落在自己的会话目录**里，会话之间不共享目录。

- **产物写相对路径**：`write_file` 写 `artifacts/{教材名称}/…`，实际落在 `<运行态根>/<自身会话目录>/artifacts/{教材名称}/…`。
- **跨会话读取用绝对路径**：运行态根内的绝对路径被直接放行，所以下游按 `<运行态根>/<产出方会话目录>/<相对路径>` 就能读到别人的产物。
- 主编在**产物面板**查看：面板按会话聚合展示（本会话 + 其全部子会话），子智能体的产物同样可见，**不需要**写进父会话目录。

## 两个值的来源（都从自己的 system prompt 读，不需要猜、不需要 echo）

| 值 | 读哪里 | 形如 |
| --- | --- | --- |
| **运行态根** | `## Workspace` 段的 `Project (…)` 行给出的绝对路径 | `/…/workspace/runtimes/631f97d0-c074-…` |
| **自身会话目录** | `## AgentStateStore Context` 段的 `AgentStateStore ID:` 行 | `main-868a7724-…` / `sub-f1f29b76-…` |

> 这两个值框架在每个会话的 system prompt 里都给出（父编排与每个子智能体都有），**不要**执行 `echo`、不要从别处抄示例值。

## 核心规范

### 1. 两类写法（只有两种）

| 用途 | 写法 | 例子 |
| --- | --- | --- |
| **读**（含跨会话输入） | **绝对路径** = 运行态根 + 产出方会话目录 + 相对路径，**原样使用** | `<运行态根>/sub-f1f29b76-…/artifacts/Python程序设计/章节目录/目录结构.json` |
| **写**（自己的产物） | **相对路径** | `artifacts/Python程序设计/第3章_循环结构/组件/知识准备_v1.0.md` |

- **禁止**把产物写进父会话目录或其它会话目录——会话之间不共享目录。
- **禁止**用相对路径去读跨会话的输入文件：相对路径落在自己空间，会误判成「文件不存在」。输入一律用注入的绝对路径。
- `write_file` **自动创建多级父目录**，因此**不需要任何 `mkdir`**。

### 2. 路径里不要出现占位符或会话 ID 拼接

- 平台**不存在** `${WORKSPACE_ROOT}` / `${SESSION_ID}` 这类占位符（hygiene-allow）：写了只会得到字面量目录名（谁都找不到）。
- 跨会话路径里那个「产出方会话目录」段来自**产出方的汇报**（§4 `artifacts`）——父编排**原样转发**，不要自己拼、不要改成相对路径、不要缩写。

### 3. 产物放在哪（统一一处）

**全部产物**（目录/知识图谱/组件/资料全文/图片/审核结论/拼装件/前言附录等）都用相对路径写在自己的会话空间，目录组织仍按 `artifacts/{教材名称}/...` 的约定（见各 Skill 与「artifacts存储规则」）。**没有「交付件」这一类**——主编可见性由产物面板聚合解决，不靠写父目录。

### 4. 汇报规范（`【TASK_RESULT】` 的 `artifacts`）

任务完成后，return 末尾必须输出唯一的 `【TASK_RESULT】` YAML 块（字段与状态取值见所在智能体定义文件）。其中 `artifacts` 登记本次**全部产出**，每条写成**运行态根相对路径** = `<自身会话目录>/<相对路径>`：

```yaml
artifacts:
  - sub-1a2b3c4d/artifacts/{教材名称}/第3章_{标题}/组件/知识准备_v1.0.md
  - sub-1a2b3c4d/artifacts/{教材名称}/章节目录/知识图谱.json
private:                       # 仅供自己排查的临时件，可省略
  - sub-1a2b3c4d/artifacts/{教材名称}/_temp/scratch.json
```

- **逐文件写全**，禁止用目录、通配符或「同上」；无文件产出写 `artifacts: []` 并在 `summary` 注明「无文件产出」。
- 平台会按这些路径核对文件是否真实存在（缺失项会在会话汇报里标出），因此**不要登记没写的文件**。
- 本文档说的「回传路径」一律指这里的 `artifacts`，父编排只信这里，不猜也不扫。

### 5. 读取他人产物

- 用**父编排在 task 中注入的绝对路径**（父从产出方 `artifacts` 拿到会话目录段后拼上运行态根再转交）。
- **不要**用 `list_files` / `glob_files` 去猜位置；**找不到文件按失败上报**（`[MISSING] <路径>`），不要自行换路径重试。

### 6. 临时脚本与草稿文件（防写入冲突空转）

需要自写临时脚本（绘图/转换/数据处理等中间用途）时：

- 统一写到 `_temp/` 或 `artifacts/{教材名称}/_temp/`，不与正式产物混放，不登记进 `artifacts` 主清单。
- **文件名一次性**：写入前先确认目标路径不存在同名文件；已存在就换带区分后缀的新文件名（如 `_v2` / 时间戳）。`write_file` 对已存在文件会被框架拒绝（必须先读后改），硬重写只会连环报错。
- **禁止对没把握的旧内容做连续 `edit_file`**：`edit_file` 按字面匹配，旧片段对不上就必然失败——同一文件连续改不中超过 1 次即换新文件名重写，不要在同一文件上反复试错消耗轮次。

## 执行方式

本 Skill 不涉及脚本。子智能体在读写文件、写汇报前加载本规范并遵循 §1（两类写法）、§4（`artifacts` 登记）。

## 输出

不产出文件。仅作为路径规范供各子智能体遵循。
