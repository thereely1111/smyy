name: jc-2-来源核查
description: 核查学科知识资料来源的相关性、完整性和格式合规性，下载学科知识和案例的所有来源原文（案例含配套资料）。产出核查报告（PASS/FAIL），缺口由 jc-2-资料查找 补充检索。
---
## 职责

1. 核查 jc-2-资料查找 产出的学科知识资料来源，剔除禁止来源、环境不匹配、弱相关条目
2. **下载所有保留来源的原文**（学科知识 + 案例），案例额外下载配套资料
3. 产出核查报告和 _索引.json。FAIL 时返回缺口清单供补充检索（≤3 轮）

## 输入

| 来源                       | 用途                                              |
| -------------------------- | ------------------------------------------------- |
| 资料全文/第X章_资料来源.md | jc-2-资料查找 产出                                |
| 目录结构.json              | 读取 os、tools                                    |
| 案例清单.json              | 读取案例 items（type、name、kb_entry_id、usable） |

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行步骤

### Step 1：来源过滤

逐条扫描，命中禁止来源 → 直接剔除。

禁止来源：个人博客、知乎、CSDN、简书、掘金、博客园、搜狐号、百家号、微信公众号、百度知道、未署名网络文章、社区文档、百度百科。

### Step 2：环境匹配检查

对所有学科知识来源逐条检查：

| 检查项    | 规则                                              | 不匹配动作       |
| --------- | ------------------------------------------------- | ---------------- |
| 操作系统  | 未提及→默认符合；提及的与`os` 一致或跨平台兼容 | 剔除，给出补搜词 |
| 工具/版本 | 未指定→默认符合；与`tools` 一致或相邻大版本    | 剔除，同上       |

### Step 3：相关性判定

基于标题+摘要快速判定高相关/弱相关/不相关。高相关保留，弱相关和不相关剔除。

### Step 4：下载原文

对 Step 1~3 保留的所有来源下载原文并落盘。

#### 4a. 学科知识 KB 来源

通过 `../jc-0-知识库检索/scripts/fetch_entry.py --fulltext {entry_id}` 下载原文件到 `资料全文/kb_{entry_id}_{name}.{ext}`。下载失败 → 剔除。

下载时**默认顺带提取原文中的图片**到 `图片/KB图片/` 并生成 `图片/KB图片/索引.json`（page 的 markdown 图片 + docx/ppt 内嵌图 + pdf 内嵌图），供 jc-3 知识准备/项目实现按需引用。

#### 4b. 案例 KB 来源

从案例清单.json 读取 `type = "案例"` 且 `usable ≠ "AI推断"` 的条目（即 KB 命中的案例），执行：

- `../jc-0-知识库检索/scripts/fetch_entry.py --case --download-assets {entry_id}` → 下载案例原文到 `资料全文/`，同时下载配套资料/代码工程到 `案例资料/{案例名}/`（自动判断：关联 git 仓库→clone，KB 内置文件→直接下载）
- 下载后回填 `资料全文/第X章_资料来源.md` 的「二、案例来源」占位节，并将案例写入 `_索引.json` 的「案例来源」段

#### 4c. 外部 URL（仅「知识库+互联网」模式执行）

> **资料来源模式（取父任务注入值，未注入一律按「仅知识库」）**：「仅知识库」模式下**不存在外部 URL 来源**（jc-2-资料查找已禁止联网检索），本步骤整体跳过；若资料来源文档中仍残留外部 URL 条目，直接剔除并在核查报告中标注「外部来源未经主编授权，已剔除」。

仅当 `资料来源模式=知识库+互联网` 时，对有 URL 的外部来源执行本地化，按以下兜底链处理：

1. **首选**：通过本 Skill 的 `scripts/fetch_url.py {url} --out 资料全文/ --name ext_{id}` 抓取网页，将图片、CSS 内联为 data URI，打包为单个 `资料全文/ext_{id}.html`（离线可读，含图片与样式）。
2. **抓取失败**（网络错误/非 200/空内容）→ 改用 `web_fetch` 抓取正文摘要兜底，保存摘要（`资料全文/ext_{id}.md`），标记 fetch_error，来源降级为仅 URL + 摘要。
3. **`web_fetch` 也失败** → 剔除该来源，不再保留。

### Step 5：剔除执行

从 `资料全文/第X章_资料来源.md` 中删除标记剔除的条目，更新来源统计。

### Step 6：知识点覆盖检查

叶子节点与剩余有效来源逐一对照。来源数为 0 → FAIL。

### Step 7：来源完整性自检

| 检查项       | 阈值                           |
| ------------ | ------------------------------ |
| 有效来源总数 | ≥ 2                           |
| 有效来源     | 至少1个原文可读                |
| KB 格式      | 含 URL + entry_id              |
| 案例来源原文 | KB 命中的案例至少 1 个原文可读 |
| 案例配套资料 | KB 命中案例的配套资料已下载    |

### Step 8：生成核查报告

生成 `资料全文/第X章_核查报告.md`，标注 PASS 或 FAIL。FAIL + 轮次 < 3 → 回退 jc-2-资料查找 补搜。

---

## PASS/FAIL 规则

| 条件                | PASS                  | FAIL     |
| ------------------- | --------------------- | -------- |
| 知识点覆盖          | 全部 ≥ 1             | 任一 = 0 |
| 有效来源数          | 全部 ≥ 2             | 任一 < 2 |
| KB 格式             | 全部含 URL + entry_id | 缺任意   |
| 案例原文（KB 命中） | ≥ 1 可读             | 全部失败 |
| 有效来源            | ≥ 1 可读             | 全部失败 |

第 3 轮仍 FAIL 标注「三轮已达上限，需人工补充」。

---

## 约束

- 逐条判定，不跳过任何来源
- 不捏造来源；缺口由 jc-2-资料查找 定向补充
- 学科知识和案例的所有保留来源必须下载原文
- **资料来源模式（取父任务注入值，未注入一律按「仅知识库」）**：「仅知识库」模式禁止一切联网下载与外部 URL 处理（Step 4c 跳过）；「知识库+互联网」模式下外部 URL 来源必须本地化为单个离线 .html 存档（图片/CSS 内联）；`fetch_url.py` 抓取失败 → `web_fetch` 摘要兜底；`web_fetch` 也失败 → 剔除该来源
- **仅知识库模式下来源不足的处理**：重试轮次内仅做 KB 换词补搜；第 3 轮仍不达标 → 按「三轮已达上限」标注 `⚠️ KB未覆盖，需人工补充`，不因缺外部来源而扩大联网检索
- KB 命中的案例必须下载配套资料
- `_索引.json` 必须生成
- 禁生成临时脚本，禁 shell 删文件
