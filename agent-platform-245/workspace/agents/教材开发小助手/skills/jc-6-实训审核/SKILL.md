## 输入上下文

- **实训组件**：实训
- **章节目录**：当前章节标题树
- **正文内容**：供对比超纲检查

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行方式

**自动化脚本 + AI 语义并列审核。脚本与AI独立运行，合并判定：任一方不通过即为整体不通过。**

### 第一步：运行自动化规则检查

```bash
python scripts/audit_practical_test.py --target <待审核内容.md> --toc <目录结构.json>
```

**脚本输出**（stdout，结构化文本）：

| 检查项     | 说明                                               |
| ---------- | -------------------------------------------------- |
| 实训数量   | 检测实训条目数，≥2 通过                          |
| 难度递进   | 检测基础/简单/综合等递进标识                      |
| 实训结构   | 检测训练要点 + 需求说明 + 实现思路及步骤 的存在性  |
| 知识点覆盖 | 统计涉及二级标题的数量与覆盖率（`--toc` 传入）   |

> 不传 `--toc` 时跳过知识点覆盖检查。

脚本独立输出审核结论（通过/不通过 + 检查项明细）。不产生任何持久化文件。

### 第二步：AI 语义审核

读取被审核文件实际内容，结合正文进行对比，独立输出审核结论。

**1. 内容质量**

- 内容是否超纲（"客观题答案需要在本章正文中找到"）
- 是否尽量覆盖每个二级标题的知识点（"习题尽量覆盖每个三级标题的内容，至少覆盖二级标题的知识点"）
- 操作题 ≥ 2 题
- 操作题是否由简单到难排列：第1题为基础操作（涉及1个三级标题或1个二级标题知识点），第2题为综合运用（涉及2~3个二级标题知识点）

**2. 实训结构**

- 结构是否完整：训练要点 + 需求说明 + 实现思路及步骤
- 训练要点是否列操作类（非理论类）
- 实现步骤是否尽量详细

**3. 思政融入**

- 实训/操作题选题是否与思政相关（如适用，选题时选择思政相关题目，并在背景中展示）

### 第三步：合并判定

脚本与AI各自独立给出通过/不通过结论。**任一方不通过 → 整体不通过**。汇总双方所有不通过点，统一输出。

## 输出格式

```
[审核结果] 通过 / 不通过

## 脚本审核：[通过/不通过]
（脚本输出的检查项明细：通过项 + 不通过项）

## AI审核：[通过/不通过]
通过项：（列出所有AI通过的检查项）
不通过项：（每项注明具体位置、问题描述、修改建议）

[综合评定]
脚本与AI合并判定：双方均通过 → 整体通过；任一方不通过 → 整体不通过。
汇总双方所有不通过点与修改建议。
```
