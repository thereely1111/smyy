## 输入

| 参数 | 路径 |
|------|------|
| 目录结构.json | `artifacts/{教材名称}/章节目录/目录结构.json` |
| 知识准备内容 | `artifacts/{教材名称}/第X章_{标题}/知识准备.md` |
| 项目实现内容 | `artifacts/{教材名称}/第X章_{标题}/组件/项目实现.md` |

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 规范

始终加载 `references/全局写作原则.md` + `用语与格式规范.md`。

## 体例输出格式

| 体例 | 输出组件 | 路径 | 结构 |
|------|----------|------|------|
| 项目式 | 【项目小结】 | `artifacts/{教材名称}/第X章_{标题}/项目小结.md` | 段落文字，≥3 行 |
| 项目任务式 | 【项目小结】 | 同上 | 同上 |

## 工作流程

### Step 1：读取

读取目录结构.json（H2 结构）、知识准备内容、项目实现内容（完整正文知识点）。

### Step 2：编写小结

| 要求 | 说明 |
|------|------|
| 内容来源 | 提取正文中的知识点 |
| 行数 | 至少 3 行 |
| 覆盖 | 每个二级标题的内容必须体现 |
| 联系 | 体现每个二级标题之间的联系 |
| 不超纲 | 不可出现正文未涉及的内容 |

### Step 3：产出

生成小结 Markdown。

## 核心约束

1. 只总结正文已有内容，不添加新知识
2. ≥3 行，每个二级标题内容必须体现
3. 语言精炼但不丢失关键信息

## 修改模式

收到 `[修改指令]` 时：仅修改指出的问题点，逐条对照修正。
