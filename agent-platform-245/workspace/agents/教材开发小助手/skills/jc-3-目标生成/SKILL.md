## 工作流程

### Step 1：读取

读取目录结构.json（体例类型、H2/H3 结构、`思政_required`）、知识概要.md（作参考骨架）、**知识准备.md、项目实现.md（正文，目标的唯一事实来源）**。

### Step 2：编写知识目标

**依据正文**：从正文（知识准备 + 项目实现）中提取**大篇幅展开**的理论知识点，据此撰写知识目标。正文未展开的知识点不写入目标。

认知层级由低到高：

| 层级 | 内容类型                                 | 句式       |
| ---- | ---------------------------------------- | ---------- |
| 了解 | 背景、概念、典型场景、发展历程、基本特性 | "了解……" |
| 理解 | 原理、思想、设计原则、机制、含义         | "理解……" |
| 熟悉 | 流程、环境、工具、配置                   | "熟悉……" |
| 掌握 | 方法、语法、基础用法、操作、策略         | "掌握……" |

可在"了解/掌握…"后接"能够区分/对比/说明"分句。禁止"学习……""理解……的重要性"等不可测表述。

### Step 3：编写技能目标

**依据正文**：从正文（知识准备 + 项目实现）中提取**大篇幅展开**的技能点，据此撰写技能目标。

句式：`能够 + [动作动词] + [对象/技术/任务]`，不可出现"了解""熟悉""掌握"。

### Step 4：编写素养目标

**思政判断**：若 `思政_required = true`，编写素养目标；若 `false`，素养目标不融入思政（可保留素养目标框架但以职业素养、工匠精神等技术相关素养为主，不写思政元素）。

与本章技术内容绑定，从学习过程中自然引申。句式：通过[学习活动/实现/理解]，培养/树立/具备/提升……。至少 2 点，不超过 4 点。

**思政落正文（硬约束）**：当 `思政_required = true` 时，素养目标中的思政元素**必须在正文（除一级标题与二级标题之间的引言、实训、习题外）里有提到**，不可仅在目标中声明而正文无对应内容。素养目标应**回填**正文中实际融入的思政元素，而非新造。

### Step 5：校验与产出

数量：知识目标 3~7 条，技能目标 3~7 条，素养目标 2~4 条。每条统一句号。产出 Markdown。

## 核心约束

1. **用词一致**：目标用词与正文（知识准备 + 项目实现）中的方法名、术语严格一致
2. **正文为准**：只覆盖正文中**大篇幅展开**的知识点/技能点，正文未展开的不写入目标；正文是目标的唯一事实来源，知识概要仅作参考骨架
3. **数量达标**：知识目标 3~7 条，技能目标 3~7 条，素养目标 2~4 条
4. **句式规范**：技能目标用"能够……"，知识目标用认知层级动词
5. **思政落正文**：素养目标的思政元素须在正文（除章引言、实训、习题外）有对应体现，且为正文实际融入元素的回填，不新造

## 修改模式

收到 `[修改指令]` 时：仅修改指出的问题点，逐条对照修正。
