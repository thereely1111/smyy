## 输入上下文

- **正文组件**：知识准备产出 + `资料全文/第X章_资料来源.md`
- **体例类型**：`目录结构.json` 顶层字段「体例类型」（项目式 / 项目任务式）
- **资料全文目录**：`artifacts/{教材名称}/第X章_{标题}/资料全文/`

> **路径（本 Skill 的输入/产出）**：**输入**文件路径由父编排在 task 中注入，是**绝对路径**（运行态根 + 产出方会话目录 + 相对路径），**原样使用**，**禁止**用相对路径去猜；**产出**一律用**相对路径**写在自己的会话空间（会话之间不共享目录），并在 `【TASK_RESULT】artifacts` 里逐文件登记（`<自身会话目录>/<相对路径>`）。完整规则见 `jc-0-路径工具`。

## 执行方式

**脚本审核 + AI 语义审核 并列运行。脚本与AI独立运行，合并判定：任一方不通过即为整体不通过。**

### 第一步：脚本侧审核（强制，优先执行）

**1.1 来源闭环检查**

```bash
python scripts/audit_knowledge.py --target <待审核内容.md> --source-md <资料全文/第X章_资料来源.md>
```

**脚本输出**（stdout，结构化文本）：

| 检查项         | 说明                                                       |
| -------------- | ---------------------------------------------------------- |
| 来源文件存在性 | 验证`资料全文/第X章_资料来源.md` 文件存在且可读          |
| 数值追溯       | 提取正文中的数值/专有名词，检测是否在来源文件中可查        |
| 孤立数据       | 来源文件缺失或存在大量无法追溯的孤立数值 → 登记`[info]` |

**1.2 代码复跑验证（章节含代码时必做，一审技术审核核心项）**

```bash
python ../jc-0-代码验证/scripts/execute_code.py <知识准备.md>
```

> 脚本位于兄弟技能 `jc-0-代码验证`，从**本技能目录**执行（与本文件 `scripts/audit_knowledge.py` 同一 cwd 口径）。

以上两项脚本合并输出审核结论（通过/不通过 + 检查项明细）。不产生任何持久化文件。

### 第二步：AI 侧审核（强制，不可跳过）

> 原文不标注 `[来源]` 块，脚本仅做数值/术语登记。逐句语义比对由 AI 完成。AI 独立输出审核结论。

**2.1 AI 逐句语义比对**

逐 H3/H4 执行：

1. **读来源**：打开 `资料全文/第X章_资料来源.md`，读取该知识点对应的来源摘要和说明
2. **逐句比对**：
   - 定义描述是否与来源一致（允许改写，不允许歪曲）
   - 步骤/操作流程是否与来源吻合
   - 数值/参数是否与来源一致
3. **找捏造（严禁胡编乱造，强制逐项核对）**：任何正文内容必须可溯源到来源原文，逐项核对以下事实性内容，**来源无支撑即判定捏造**：
   - 方法名 / 函数名 / API 名称
   - 参数名、参数默认值、参数含义
   - 版本号、年份、发布时间
   - 数值、数据、百分比、性能指标
   - 对比结论（如"A 优于 B""X 比 Y 快"）
   - 引文、出处、人名、机构名
   - 步骤、操作流程、命令、配置项
   - 运行结果、输出样例
   > 凡来源原文中不存在的上述内容，一律判定为捏造风险，**不得以"合理推断"为由放过**；来源未覆盖的知识点不得自行补造。
4. **输出**：`[逐句比对通过 N/N]` 或 `[捏造风险 @段落X: "具体表述" → 来源无此内容]`

**2.2 AI 常规审核**

**内容结构：**

- 展示形式是否图→表→文字优先
- 理论类是否按背景→概念→分类→作用→场景→原理→例子→比较顺序
- 操作类是否先介绍作用再举例子
- 结果后是否解释：意义→应用→比较
- 标题关系是否合理（同级承接/并列，上下级总分）
- **★ 案例类章节结构差异检查**：不同 H3 是否使用了不同结构模板，禁止全部 H3 使用同一"Prompt→代码→审查"模式

**例子质量：**

- 是否贴近读者生活，阳光积极，具有实际意义
- 是否涉及敏感词/负面内容

**用语质量：**

- 语句书面化，除体例允许的引导语外不使用人称代词
- 术语统一，用词一致，总分说法一致
- 是否出现"当前""去年"等模糊时间词

**代码结果配对：**

- 每个 `代码X-N` 是否有对应的运行结果段落
- 代码输出结果是否与正文描述一致

**提示词运行结果完整性：**

- 凡含"提示词""借助AI""AI生成"等提示词驱动型内容的 H3/H4，必须满足四段式「描述→提示词→描述→结果」
- 「结果」段为必选：提示词后必须紧跟运行结果（代码块 `代码X-N` + 来源标注，或引用块 `结果X-N`），并标注来源（"以下为AI根据提示词生成" / "以下为内置 AI 实际运行输出"）
- 禁止：提示词后无结果段，或仅用"AI 生成原型后……"的笼统描述替代结果
- 判定：违反上述任一 → 该组件审核不通过，退回 `jc-3-知识准备` 补充结果段

**题注引用（强制）：**

- 逐一检查所有图/表/代码，是否紧邻其前一行有标准引用句式（如图X-N所示/如表X-N所示/如代码X-N所示）
- 引用句式必须与 `题注与编号规范.md` 一致（逗号隔开或定语形式）
- 待补齐图片同样需要引用句，引用句中不标注"待补齐"
- 严禁出现无引用句的图/表/代码

**思政融入：**

- 是否自然融入，每章思政点不重复

---

### 第三步：合并判定

脚本侧（来源闭环 + 代码执行）与AI侧（逐句比对 + 常规审核）各自独立给出通过/不通过结论。**任一方不通过 → 整体不通过**。汇总双方所有不通过点，统一输出。

### 第四步：产出章节摘要（审核通过后强制执行）

> 审核通过后，从知识准备正文提取术语/概念/符号，产出 `chapter_summary.json`，作为 `jc-6-一致性审核` 的输入。**审核不通过时不产出**，退回修改后重新审核通过时再产出覆盖旧文件。

**产出路径**：`artifacts/{教材名称}/第X章_{标题}/摘要/chapter_summary.json`

**提取规则**：

1. **concepts**：知识准备正文中通过 **加粗** 或 `「」` 标注的核心概念，`definition` 从正文原句提取。逐节遍历，不遗漏。
2. **terms**：正文中首次出现并给出英文全称的专业术语，每个术语仅记录首次出现位置。
3. **symbols**：公式、代码块中使用的数学符号或关键变量。
4. **所有内容从知识准备正文原文提取，不自行编造**。

**Schema 字段**（固定，与已入库章节 `chapter_summary.json` 一致，确保跨章可解析）：

| 字段                            | 类型     | 说明                                       |
| ------------------------------- | -------- | ------------------------------------------ |
| `concepts[].name`             | string   | 概念中文名                                 |
| `concepts[].aliases`          | string[] | 别称                                       |
| `concepts[].definition`       | string   | 一句话定义（从正文提取原文）               |
| `concepts[].first_section`    | string   | 首次出现小节编号                           |
| `concepts[].related_sections` | string[] | 相关小节                                   |
| `terms[].term`                | string   | 术语名                                     |
| `terms[].full_en`             | string   | 英文全称（无则空字符串）                   |
| `terms[].abbreviation`        | string   | 缩写（无则空字符串）                       |
| `terms[].first_section`       | string   | 首次出现小节编号                           |
| `terms[].related_api`         | string   | 关联 API（无则空字符串）                   |
| `symbols[].symbol`            | string   | 符号表示                                   |
| `symbols[].meaning`           | string   | 符号含义                                   |
| `symbols[].type`              | string   | variable / parameter / function / operator |
| `symbols[].first_section`     | string   | 首次出现小节编号                           |

> 所有字段必须存在，无对应内容时填空数组 `[]` 或空字符串 `""`。JSON 使用 UTF-8 编码，`ensure_ascii=False`。

## 输出格式

```
[审核结果] 通过 / 不通过

## 脚本审核：[通过/不通过]
（脚本输出的检查项明细：来源闭环检查 + 代码执行结果）

## AI审核：[通过/不通过]
通过项：（列出所有AI通过的检查项）
不通过项：（每项注明具体位置、问题描述、修改建议）

[综合评定]
脚本与AI合并判定：双方均通过 → 整体通过；任一方不通过 → 整体不通过。
汇总双方所有不通过点与修改建议。
```
