## 一、范式来源

本骨架的工程结构参考自一份已落地的 Vue3 + TS 源码工程，其形态是「单文件 HTML 交付物 + 完整源码工程」双形态并存。该工程规模为 `src/` 46 个文件、约 19,360 行。

关键取舍：**接受多文件 `dist/` 产物、不再支持双击打开**，换取代码拆分、缓存与静态托管维护能力。数模演易原型 v2 是 1.88 MB 单文件（360 个函数），开发期直接改单文件已接近不可维护，转源码工程是必要的下一步。若仍需单文件交付形态，应保留独立构建脚本，不走主构建链。

## 三、四个最难自己写对的基础设施

这四块覆盖了认证、流式通信、状态联动三类问题，是本范式最有价值的部分。

### 3.1 统一请求层

**解决的问题**：JWT 过期、401 重放、并发刷新去重、超时、SSE 长连接。

- **本地预判过期 + 静默刷新**：解析 JWT `exp`，过期则先 refresh 再发业务请求
- **401 重放一次**：服务端返回 401 时 refresh 后重放
- **并发去重**：模块级 `refreshInFlight` 持有进行中的 Promise，多个 401 共享同一次刷新
- **认证端点排除**：`/api/auth/*` 不参与刷新重试（它本身就是换 token 的）
- **错误类型携带 status**：错误文案优先取后端 `message`，兼容 `detail` 字段
- **流式请求单独出口**：不解析 JSON、不设超时（长连接），仍自动带 Bearer 且 401 静默刷新一次

### 3.2 会话恢复

**解决的问题**：刷新页面后「token 还在但用户信息没了」导致的误判未登录。

- **全局只恢复一次**：模块级 `restorePromise`，`main.ts` 触发、路由守卫 await 同一个 Promise
- **三级降级链条**：`/me` 校验 → 失败则 refresh 静默换新 → 都失败才清会话
- **双模式判定口径**：real 模式要求「有 token 且有 userId」才算登录，避免本地演示账号被误判

### 3.3 AG-UI 与 HITL

**解决的问题**：智能体流式对话 + 需要用户填表时的中断与恢复。

协议流程：

```
1. POST { threadId, runId, messages:[userMsg] }
2. SSE 推送 RUN_STARTED / TEXT_MESSAGE_* / TOOL_CALL_*
   需要用户填写时，最后事件是
   RUN_FINISHED { outcome: { type:'interrupt', interrupts:[...] } }
3. 用户提交后再次 POST 同一 (threadId, runId)，body 带
   { threadId, runId, messages: [], resume:[{ interruptId, status, payload }] }
4. 后端继续推送直至 RUN_FINISHED { outcome: { type:'success' } }
```

**四条容易踩坑的约定**：

| 约定 | 原因 |
| --- | --- |
| 每轮**新消息**生成新 `runId` | 避免与未结束的旧 run 冲突 |
| **resume 复用同一 `runId`** | 否则后端认不出是哪次中断 |
| `threadId` 前缀固定 `main-` | 后端与平台前端以该前缀识别新建会话；不一致会导致产物目录分叉 |
| `threadId` 与 `runId` **一并持久化** | 只存 `threadId` 会导致刷新后点提交失败 |

**宽容取值策略**：从多个候选字段名中取值（`delta`/`text`/`content`/`chunk`/`value`），因为后端字段名可能随版本变化。这个防御性写法值得照搬。

**表单中断登记**：把待填表单上报到后端（内存登记），刷新/重访后可查回重建。上报失败不影响当前 UI，只影响后续恢复 —— 这是正确的降级设计。

### 3.4 产物面板数据源

**解决的问题**：产物树与文件内容的获取、选中态、随会话切换自动刷新。

- `watch(() => chat.threadId, ...)` + `immediate: true` —— 切会话自动重载，直接进入已打开会话也能立即拉取
- **接口不可用一律降级为空态**：401/404/网络错 → 空树 + 记原因，**不抛错不弹 toast**，保证工作台不因数据源缺失而不可用

## 四、mock/real 双模式

骨架期最该学的工程化设计：

```ts
const backend = {
  mode: 'mock',                                    // 全局模式
  stageReal: [false, false, false, false, false],  // 按阶段粒度切 real
  baseUrl: 'http://127.0.0.1:8000'
}

export function isStageReal(stage: number) {
  return backend.mode === 'real' && !!backend.stageReal[stage]
}
```

每个数据函数都是双路：

```ts
export async function fetchBooks(onlyDone = true): Promise<Book[]> {
  if (backend.mode === 'real') { /* TODO: GET {baseUrl}/books */ }
  return BOOKS.filter(b => (onlyDone ? b.done : true))   // mock 兜底
}
```

**价值**：后端未就绪时前端可完整跑通交互；后端就绪后**逐模块切 real**，不需要一次性全量联调。同时保留「后端挂了也能演示」的能力。

> **对数模演易的建议**：照搬此范式，且可进一步按**问题（Q1–Q4）**切分 real 粒度 —— 四个问题求解链路独立，可以一个一个接。

## 五、构建配置要点

### vite.config.ts

```ts
const backendTarget = env.VITE_BACKEND_TARGET || 'http://localhost:8080'
const proxyOptions = {
  '/api':    { target: backendTarget, changeOrigin: true },
  '/agui':   { target: backendTarget, changeOrigin: true },   // AG-UI 流式接口
  '/public': { target: backendTarget, changeOrigin: true },   // 公开接口
}
```

- **代理是必需的，不是可选优化**：后端未配 CORS，浏览器直连会被拦截。因此前端代码**一律写相对路径**
- `base: './'` —— 相对路径 base，便于任意子路径部署
- `server.strictPort: true` + `host: true` —— 端口固定、监听 0.0.0.0（便于局域网演示）
- **`preview` 也要配 proxy** —— 预览构建产物时同样需要转发后端请求
- `build.assetsInlineLimit: 4096` —— 小于 4KB 内联为 data URI

### 已知坑

> 如果根目录出现 `vite.config.js`（`vue-tsc -b` 的编译产物），Vite 会**优先加载它而忽略 `.ts`**。
> 修复：把 `tsconfig.node.json` 的产物目录改到 `node_modules/.tmp`。

**这是 `vue-tsc -b` + Vite 组合的真实陷阱**，必须一并照搬这个修复。

### 环境变量设计

只放少量变量，且**只写人类可读的名字，不写 UUID**：

```bash
VITE_AUTH_MODE=real                        # real 对接后端 / mock 本地演示账号
VITE_BACKEND_TARGET=http://localhost:8080  # Vite 代理目标（agent-platform-java）
VITE_SMYY_AGENT_NAME=数学建模解答助手        # 智能体中文目录名（对应后端 workspace/agents/）
VITE_SANDBOX_MODE=real                     # 沙箱：real 走后端 / mock 本地假会话
VITE_ANALYSIS_MODE=real                    # 分析通道，与沙箱开关**分开**
```

智能体的 agentId = `UUID.nameUUIDFromBytes(目录名)`，由代码在**运行时**推导 —— 算法在 `src/utils/nameUuid.ts`，读取处 `src/config/index.ts`。改名只改 `.env.local` 一处，不用手算 UUID、不用改代码（仍可用 `VITE_SMYY_AGENT_ID` 覆盖，仅供指向临时实例）。

## 八、动画剧场架构

参考工程无对应物，数模演易需自行设计。原型 v2 的每幕是一个自包含单元，结构高度一致：

```
<section class="scene" id="s1" data-title="一 · 同一套微网，四个问题">
  <style>  :host(.reduce) .scene{transition:none}  ...
  <div class="wrap">
     <section class="stg">...</section>       ← 节拍单元，加 .in 类露出
     <script id="DATA"> {...} </script>       ← 内嵌 JSON
     <script>  function tlRun(i){...}          ← 时间轴
               function beatsAuto(){...}       ← 扫 .wrap > * 自动排节拍
               function revealCanvas(el){...}  ← 画布显隐
               function plotStack(...)         ← 同 canvas 拆上下子图
               function note(g,text,px,py,o)   ← 白底注块自动避边界
     </script>
  </div>
</section>
```

**迁移策略**：不要重写绘制逻辑。把每幕抽成一个 `components/theater/scene/SceneN.vue`，`<script>` 内容放进组件的 `onMounted`（原始 JS 可直接保留），`<style>` 放进 scoped style，`<template>` 承接 `wrap` 结构。这是**搬迁而非重构**，风险最低。

**三个必须避免复发的问题**：

1. **切幕必须重置目标幕的图** —— 进入一幕时对该幕图表 `removeAttribute('data-done')` + 清空画布，交给节拍重画。否则会停在半截。
2. **`measureText()` 必须容错** —— 某些环境返回 undefined，不能链式取 `.width`。
3. **`prefers-reduced-motion` 不得自动降级** —— 本机 `VisualFXSetting=3` 会让 Chromium 报 reduce。动效默认开、页内开关控制。

## 十、结论

参考工程的工程价值集中在**四个「难写但可搬」的模块**：统一请求层、会话恢复、AG-UI 客户端、产物面板数据源。这四块覆盖了认证、流式通信、状态联动三类最难自己写对的基础设施。

需要**重新设计**的是业务层：赛题、四问求解链路、动画剧场、会员额度邀请，在参考工程里没有对应物。

需要**仅借鉴结构、不借鉴皮肤**的是样式：两套设计系统不能混用。
