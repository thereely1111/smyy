问题二 · 冲突消解
问题二的核心约束

一个用频计划最多调一个参数 频移 ±10Δf、时移 ±5Δt，优先级 A > B > C，撤销只作兜底。

问题一告诉我们「哪里有冲突」，问题二要回答「怎么把冲突消除」。题面对消解动作给了严格限制：每个装备只能从 频段平移、时间平移、撤销 三者中选一个执行，且平移有硬上限。这不是一道"随便挪挪就行"的题——它真正考的是在受限动作空间里如何取舍。

消解的艺术可以拆成三问：让谁动（原则上让低优先级方）、动多少（在能消掉冲突的前提下尽量小）、动哪个参数（频段或时间，选那个「挪一点点就够」的自由度）。这三问的答案，共同构成了本题的消解策略。

① 最多一个参数

"一个用频计划只能调整其中一个参数或撤销"

不能同时既调频段又调时间。因此每一步都要在「频移 / 时移 / 撤销」中择一——选择的标准是：哪个动作能消掉当前冲突、且代价最小。

这条约束把问题从"连续优化"压缩成了离散选择：每个冲突对的解决方式只有有限几种。

② 平移上限

"频段、时间调整的最大平移幅度分别为 10Δf、5Δt"

频移窗口 [-10, +10]Δf，共 20 个可选的整数偏移；时移窗口 [-5, +5]Δt，共 10 个。注意频域资源总量只有 100Δf，一次 10Δf 的平移相当于挪动了 1/10 的整个频段。

这是问题三（无上限）与问题二的核心区别：问题二里「只要挪得够远就能避开」，问题三里却只能靠重新规划。

③ 优先级 A > B > C

"A 类最高、B 类其次、C 类最低，高优先级应尽量保持"

实际含义：消解时让 低优先级那方动，高优先方保持原位。A 类 20 件、B 类 50 件、C 类 80 件，因此绝大多数冲突都能"让 C 类让路"。

A-A 冲突最棘手（谁都不想动），只能让其中一方微移或撤销——但 A 类数量少，这类冲突占比很低。

约束的数学表述 为什么它是离散的

设装备 i 的原参数为 (fsi, fei, tsi, tei, ivi, ni)。 // 决策变量：每件装备至多一个动作 动作 ai ∈ { 频移 δf, 时移 δt, 撤销, 不动 } 约束： |δf| ≤ 10, |δt| ≤ 5, 且 δf 与 δt 不可同时非零 // 目标：消解后冲突对 = 0，且代价最小 min Σi [ w1·|δi| + w2·1{ai=撤销} · Mi ] s.t. 对所有 (i,j)：调整后无时频重叠 其中 Mi 按优先级递增（C 撤销代价最小，A 撤销代价最大）

这个整数规划模型就是问题二的"满分形态"。实际比赛中，N=150 规模直接用 ILP 求解器也未必秒出，所以主流做法是贪心快速出可行解，再用局部搜索 / 元启发式做改进——我们下一页就展开。

算法思路

先保 A，再调 B，最后看 C 按优先级从高到低处理，每次让低优先级那方做最小幅度的可行调整。

消解不必一次性求全局最优（那会是 ILP），而可以 逐对消解 + 每次贪心选最优动作。对 N=150 的规模，这个思路足够快；更关键的是，它天然匹配题面「尽量减少调整幅度、尽量减少被调整数量」的偏好——因为贪心每次都从最小幅度开始试探。

下面的伪代码是本题最核心的一段逻辑，也是论文里必须写清楚的算法主体。请注意它的三个要点：逐对处理（每次只解决一对冲突）、低优先方让路（保护高优先级）、幅度从小到大（代价局部最小）。

主循环 逐对贪心消解

输入: equip[], 优先级 P[·] ∈ {1,2,3} 输出: actions[] = [{id, type, delta}] 循环直到无冲突: 1. 找任意一对冲突 (i, j) 2. low ← P[i] < P[j] ? i : j // 低优先方负责让 high ← 另一方 // 高优先方保持 3. 尝试频移 low: δ ∈ [0,±10] 从小到大 若频移后 low 与 所有其他装备无冲突: record {low, "freq", δ}; 更新 low 的频段; continue 4. 尝试时移 low: δ ∈ [0,±5] 从小到大 若时移后 low 与 所有其他装备无冲突: record {low, "time", δ}; 更新 low 的时间; continue 5. 撤销 low: record {low, "cancel"}; 标记 low 失效

关键在第 3、4 步的"与所有其他装备无冲突"：不是只躲开当前对手，而是保证移动后不会撞上别人——这叫可行移动，是贪心不至于"按下葫芦浮起瓢"的前提。

A-A / 同优先级冲突的特殊处理

两边优先级相同时，不能用上面的"让低优先方动"规则。此时按以下次序处理：

  • 先让涉及冲突数较少的一方尝试频移（幅度最小优先，仍需在 ±10Δf 内）
  • 若都不行，再尝试时移（±5Δt 内）
  • 仍不行，则撤销其中一方——优先撤销被更多冲突波及者（牺牲它可一次消掉更多冲突）
A 类仅 20 件，A-A 冲突对很少；这一分支命中频率低，但论文里必须交代清楚，否则会被质疑"同优先级怎么办"。

为什么贪心是合理的 三条题面偏好 → 三条算法选择

偏好一

"尽量减少被调整的用频计划数量" → 一次频移/时移可能同时消掉该装备与多个对手的冲突，贪心优先选「一动多得」的动作。

偏好二

"尽量减少调整幅度" → δ 从 1 开始、由小到大试探，第一个可行解即最小幅度解，无需枚举全部。

偏好三

"A 类应尽量保持" → 永远让低优先级方"让路"，A 类的位移被视为最后手段。

消解算法的可改进方向 冲高分用

  • 全局优化（ILP / CP-SAT）：把贪心换成整数规划，目标 = 撤销数×大权重 + 调整幅度之和，可用求解器直接求最优。
  • 邻域搜索：贪心出初解后，用 Tabu Search / 模拟退火微调，进一步压低撤销数与幅度。
  • 冲突图连通分量分解：把冲突图拆成互不影响的子图，各子图独立求解后再合并，降低问题规模。
  • A-A 子图的独立集 / 顶点覆盖：在 A-A 冲突图上求最小顶点覆盖，即"最少撤销几件 A 类"。

方法论定位

问题二是经典的 约束满足 + 优先级调度 问题：贪心能快速出可行解，ILP 能出更优解，图论能处理特殊子结构（如 A-A 子图）。三者互补，构成完整的求解体系。

评估指标

论文里建议给全：总撤销数、A 类撤销数（理想为 0）、平均调整幅度、消解后冲突对数（必须为 0），并可对贪心与 ILP 两版方案做对比。
