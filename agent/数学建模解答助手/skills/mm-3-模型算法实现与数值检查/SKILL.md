# 模型算法实现与数值检查

## 实现要求

模型、变量、目标、约束、算法和验收检查必须能追溯到题目契约或审核后的分析结论。不得在代码阶段擅自换模、放松约束或补造题目条件。

### 优化与调度

- 用明确索引集合表达时间、设备和场景。
- 标出变量单位、上下界、整数/连续属性和时间步长。
- 显式实现目标、资源守恒、状态递推、初末状态、变量边界、互斥逻辑和终端条件。
- Big-M 使用可证明的紧上界，不使用无依据的大常数。
- 记录求解器名称、兼容版本、求解状态、目标值和 gap。
- 不可行时导出 IIS（若支持）或逐组禁用约束定位；不能擅自放松约束。

### 预测与统计学习

- 时间序列按时间切分，禁止随机打乱和未来信息泄漏。
- 同时提供题目要求的朴素基线与主模型。
- 保存训练/验证区间、特征列表、预测索引、超参数、模型版本和 seed。
- 缩放器、特征选择和其他拟合步骤只能使用训练集。
- 样本不足时降低复杂度并记录限制。

### 仿真、随机优化与鲁棒性

- 固定并记录 seed，区分随机数发生器和场景采样方法。
- 显式记录场景数量、概率/权重、分布参数和风险度量。
- 逐场景检查可行性，不能只检查平均结果。
- 报告均值、分位数或置信区间所需的原始统计信息。

## 通用代码结构

将数据读取、输入校验、模型构建/训练、求解或预测、后处理、诊断和写出拆分为小函数。参数从 CLI 或配置文件传入。使用 `logging` 记录阶段、输入规模、耗时、求解状态和错误上下文。

异常要带可操作提示并非零退出；不要捕获后继续写出结果。写出前检查有限数值、字段完整性、行数、单位和主键。

## 数值检查清单

运行后应在 `results/validation.json` 记录：

- 求解/训练/仿真状态是否完成
- 约束残差、资源守恒和状态递推误差
- 变量上下界、非负性、互斥逻辑和终端条件
- 输出行数、主键唯一性、字段完整性和单位
- 预测与真实值索引对齐、基线对比和评价指标
- 随机 seed、场景覆盖、置信区间/分位数
- 异常值、非有限值、越界值和数量级检查

代码阶段只做静态检查，无法凭源码确认的项目标记 `NOT_TESTED`；不得把源码可解析或依赖已列出写成模型运行成功。
